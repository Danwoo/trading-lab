# 시세 데이터 소스 키 발급 — data.go.kr 금융위 · OpenDART · Alpaca

> **보류 해제 (2026-08-07 리드 결정).** 키는 `.env` 에서 받는다 — 암호화된 워크스페이스 설정
> 저장소는 짓지 않기로 했으므로 「저장소가 없어 보류」의 근거가 사라졌다. 아래 절차대로 발급받아
> `backend-service/app/.env.development` 의 해당 항목에 넣으면 그 소스가 바로 열린다(변수명은 각
> 절에 명시). 넣은 값은 로그·API 응답·예외 메시지에서 자동으로 가려진다(`app/utils/redaction/`).
>
> **에이전트는 이 세 소스에 가입하지 않는다.** 가입·이메일 인증·키 신청은 전부 사람이 한다
> (이 레포에서 실제로 계정 생성 사고가 났던 항목 — CLAUDE.md·오더 #2 금지 조항). 이 문서는
> 그 사람이 아침에 그대로 따라 할 수 있게 절차를 정리한 것이다.
>
> **신뢰도 표기를 각 절차 옆에 남긴다.** 이 문서를 쓴 백엔드 워커는 WebSearch/WebFetch 도구가
> 없다(역할 도구 프로필 — 기술 조사는 설계 시점에 senior 가 하고 워커는 조사된 명세를 소비한다).
> 그래서 아래 절차 중 일부는 **이 레포가 이미 검증한 사실**(다른 서비스가 실제로 그 API 를 쓰고
> 있다·설계 문서가 조사해 기록한 라이선스/한도)이고, 일부는 **오늘 시점 화면을 직접 열어보지
> 못한 일반적 패턴**이다. 후자는 진행 전에 사람이 실제 화면과 대조해 확인한다 — 특히 메뉴 이름·
> 승인 소요 시간은 포털이 개편되면 바뀔 수 있다.

## 공통 원칙

- 키는 **각자 자기 것을 발급**한다 — 팀 키를 공유하거나 코드·저장소에 커밋하지 않는다
  (NFR-002, `.docs/4-아키텍처/시세적재-구현설계.md` MD-AD-20).
- 발급받은 키는 `.env.development`(또는 배포 환경변수)에만 넣는다. `.env.*` 는 이 레포에서
  gitignore 대상이며, 그것이 실제로 막고 있는지는
  `backend-service/scripts/verify_data_key_env_boundary.py` 가 매 실행 확인한다.
- **OpenFIGI 키는 선택**이다 — 없어도 별칭 매핑이 동작하고 배치 한도만 낮다
  (`MARKET_DATA_OPENFIGI_KEY`).
- 이 세 소스를 고른 이유(라이선스·제3자 제공 가부·한도)는 이미 조사·확정돼 있다 — 절차만
  다시 조사할 필요는 없다: [시세-데이터-파이프라인 §4.5](../4-아키텍처/시세-데이터-파이프라인.md#45-확정된-소스-2026-07-29)
  ·이슈 #230 (옛 레포 번호 — 이 레포에서 열리지 않는다).

## 1. data.go.kr — 공공데이터포털 (금융위원회 오픈API, 시세·종목·재무)

**신뢰도**: 포털 계정·활용신청 메커니즘 자체는 **이 레포가 이미 실사용 중인 패턴**으로 확인됨
(`.docs/6-도구/외부서비스모니터링.md` 의 ePost 주소 API 도 같은 data.go.kr 포털의
`serviceKey` 발급 방식을 쓴다 — §2.1). **금융위 시세 API 를 지목한 정확한 검색어·메뉴 경로는
오늘 화면 기준 미확인** — 아래 ⚠ 표시 단계는 사람이 방문해 확인한다.

1. https://www.data.go.kr 접속 → 회원가입(개인 또는 기업 회원 — 개인으로 충분).
2. 로그인 후 검색창에 **"금융위원회_주식시세정보"**(또는 "금융위원회_주식시세정보 조회 서비스")로
   검색한다. ⚠ 정확한 서비스명은 포털 개편에 따라 바뀔 수 있다 — [시세-데이터-파이프라인
   §4.5](../4-아키텍처/시세-데이터-파이프라인.md)가 이 API 를 "국내 시세·종목마스터·재무" 소스로
   지목한 근거(이슈 #230)를 먼저 확인하고, 같은 제공기관(금융위원회)의 상장회사 시세·종목 관련
   오픈API를 찾는다.
3. 서비스 상세 페이지에서 **"활용신청"** 버튼 클릭 → 활용 목적(예: "개인 연구/백테스트") 작성 →
   신청.
4. **승인 대기.** data.go.kr 는 API 마다 자동승인/수동승인이 갈린다 — 공공데이터(비제한) API 는
   보통 즉시~1일 이내 자동 승인되는 경우가 많다(오더 #2 관련 리드 결정문의 "이용허락범위
   제한 없음" 표기와 일치). 승인 소요는 확인 못 함 — 신청 후 마이페이지에서 상태를 본다.
5. 승인되면 **마이페이지 → 개발계정 상세보기**에서 **일반 인증키(Encoding/Decoding)** 를 확인한다.
   - **Encoding 인증키**를 쓴다 — URL 쿼리 파라미터(`serviceKey=...`)에 그대로 넣는 값이다.
     Decoding 키를 그대로 쿼리에 넣으면 이중 인코딩으로 `Unauthorized Key` 가 난다(흔한 실수).
6. 한도는 **10,000회/일**(신청 즉시 적용, 이슈 #230). 초과 시 익일 자정(KST) 리셋.
7. `backend-service/app/.env.development` 에 넣는다:
   ```dotenv
   MARKET_DATA_GOKR_SERVICE_KEY=<발급받은 일반 인증키(Encoding)>
   ```
   비워 두면 국내 패널이 기동을 막지 않고 "이 항목이 비어 있습니다 + 발급 경로"를 사유로 낸다.

## 2. OpenDART (금융감독원 전자공시, 공시·재무)

**신뢰도**: **이 레포가 이미 실사용 중** — `disclosure-mcp-service` 가 `USE_REAL_API=true` 일 때
이 키로 실제 호출한다(`disclosure-mcp-service/app/clients/disclosure/disclosure_client.py`,
파라미터명 `crtfc_key` 확인됨). 아래 발급 절차 자체는 오늘 화면 기준 **미확인**(⚠).

1. https://opendart.fss.or.kr 접속 → 우측 상단 **"인증키 신청/관리"**(또는 회원가입 후 동일 메뉴)
   → 회원가입(이메일 인증 필요할 수 있음).
2. **"인증키 신청"** 에서 이용 목적을 적어 신청한다. OpenDART 는 보통 **즉시(또는 매우 빠르게)
   인증키를 발급**하는 것으로 알려져 있다 — 승인 대기가 사실상 없는 경우가 많다는 것이 일반적으로
   알려진 동작이나, ⚠ **오늘 시점 실제 승인 방식(즉시/검토)은 미확인**이다.
3. 발급된 **40자리 인증키**를 확인한다 — 마이페이지의 "인증키 신청/관리"에서 언제든 재확인 가능.
4. 한도는 **개인 20,000회/일, 분당 1,000회**(이슈 #230). 상업적 이용도 FAQ 가 허용을 명시한다고
   조사돼 있다(이슈 #230, "FAQ 가 상업이용 허용 명시" — FAQ 원문 링크는 재확인 필요).
5. `.env.development` — **이미 이 레포에 자리가 있다**:
   ```dotenv
   # disclosure-mcp-service/app/.env.development
   USE_REAL_API=true
   DISCLOSURE_API_KEY=<발급받은 40자리 인증키>
   ```
   `USE_REAL_API=false`(기본값)로 두면 이 키 없이도 내장 mock 데이터로 서비스가 그대로 뜬다
   (FR-013 "키 없어도 기동" 과 같은 방침 — 이 서비스가 이미 그 패턴의 실례다).
   시세 적재 어댑터(오더 #2 Phase 2, 국내 공시·지분 소스로 OpenDART 를 쓰는 경우)의 변수명은
   그 어댑터가 확정한다.

## 3. Alpaca (미국 시세 — 일봉·분봉)

**신뢰도**: 이 레포에 아직 통합된 코드가 없어(오더 #2 는 Phase 1 까지만 — 미국 유료·가입형
소스 어댑터는 이번 범위 밖) 실사용 근거는 없다. 아래는 Alpaca 의 잘 알려진 대시보드 기반
키 발급 흐름이며, ⚠ **오늘 시점 화면 문구는 미확인**이다. 진행 전 공식 문서
(https://alpaca.markets/docs) 로 재확인을 권장한다.

1. https://alpaca.markets (또는 https://app.alpaca.markets/signup) 에서 이메일로 가입.
   **증권 계좌 개설이 아니다** — 시세 데이터(Market Data API) 이용에는 브로커 실계좌가 필요
   없고, 가입만으로 발급되는 **Paper(모의) 계정** 으로 충분하다(이슈 #230 이 이 소스를
   "B 등급 — 가입·신청만, 계좌 불요"로 분류한 근거).
2. 가입 후 대시보드(https://app.alpaca.markets) 좌측 메뉴에서 **API Keys**(또는 "Your API Keys")
   섹션으로 이동한다.
3. **"Generate New Key"** 로 **API Key ID** 와 **Secret Key** 한 쌍을 발급한다. **Secret Key 는
   생성 시점에만 전체가 노출**되므로 그 자리에서 안전한 곳(비밀번호 관리자 등)에 저장한다 —
   재발급하면 이전 키는 즉시 무효화된다.
4. 한도는 **분당 200회**, 데이터는 **IEX 소스 기준 2016년~**(이슈 #230). 30일 사전 서면통지
   조항이 문서화돼 있어(이슈 #230) 오픈소스 배포 시 이 조건을 사용자에게 그대로 안내해야 한다.
5. `backend-service/app/.env.development` 에 **한 줄로** 넣는다 — Key ID 와 Secret 을 콜론으로 잇는다:
   ```dotenv
   MARKET_DATA_ALPACA_KEY=<API Key ID>:<Secret Key>
   ```
   형식이 깨지면(콜론이 없거나 한쪽이 비면) 401 을 받기 전에 어댑터가 "키 없음"으로 막는다 —
   "키가 틀렸다"와 "형식이 틀렸다"가 구분되도록.

## 4. 토스증권 Open API (2단 감시 — 호가·분봉·현재가)

2026-05 사전신청 시작, **단계적 롤아웃 중**이라 즉시 발급이 안 될 수 있다. 국내(KRX)·미국을 한 API 로 다룬다.

1. `corp.tossinvest.com/ko/open-api` 에서 **사전 신청**. 순차적으로 오픈 알림이 온다.
2. 오픈 후 PC 웹에서 `client_id` · `client_secret` 발급.
3. 인증은 **OAuth 2.0 client credentials** — `/oauth2/token` 으로 교환한 뒤 `Authorization: Bearer {access_token}`.
4. 베이스 URL 은 `https://openapi.tossinvest.com` **하나뿐이다 — 샌드박스가 없다.**

⚠️ **샌드박스가 없다는 것이 이 소스의 성격을 정한다.** 첫 주문이 곧 실거래이므로 **주문 로직은 KIS 모의계좌에서 개발**하고, 토스는 **시세·호가·분봉 소스로만** 쓴다.

**일봉 대량 적재에는 쓰지 않는다** — `candles` 가 한 번에 200봉이라 전 종목 10년 일봉이 3만 회를 넘는다. 일봉은 data.go.kr 이 날짜별 전종목으로 준다.
**분봉 과거 적재에는 쓴다** — `before`/`nextBefore` 로 거슬러 올라간다. 후보 200종목 1년치가 약 9.6만 회로, 한 번만 돌리면 된다. 역할 구분은 [시세 데이터 파이프라인 §4.6.3](../4-아키텍처/시세-데이터-파이프라인.md).

⚠️ **호출 한도(rate limit)를 확인하지 못했다.** 문서 색인에는 있다고 표기돼 있으나 원문을 못 봤다 — 2단 폴링 주기가 여기서 갈리므로 키를 받으면 가장 먼저 확인한다.

## 5. 자본변동(수정주가 계수) — 데이터셋마다 라이선스가 다르다

시세는 **원주가만** 온다. 액면분할·무상증자 보정을 하려면 자본변동을 따로 받아야 하는데, 여기서 갈린다.

| 소스 | 라이선스 | 쓸 것인가 |
|---|---|---|
| 금융위원회_**주식권리일정정보** (`publicDataPk=15059609`) | **공공누리 제2유형 — 상업적 이용금지.** 상업 활용 시 한국예탁결제원과 별도 계약 | ❌ 호스팅 모드로 가면 깨진다 |
| **OpenDART** — 주식의 총수 현황 · 액면분할 결정 공시 | 상업 이용 허용 | ✅ 이쪽 |

⚠️ **같은 포털이라도 데이터셋마다 이용허락범위가 다르다.** 주식시세정보가 "제한 없음"이라고 해서 포털 전체가 안전하다고 넘겨짚지 않는다. **새 데이터셋을 쓸 때마다 그 페이지의 이용허락범위를 직접 확인한다.**

## 확인이 필요한 항목 (사람이 실제 화면에서 검증)

| 항목 | 왜 불확실한가 |
|---|---|
| **`basDt` 단독으로 전 종목이 오는가** | 복수 실사용 사례가 그 형태를 쓰지만 **공식 명세 원문(활용가이드 PDF)을 못 봤다.** 전 종목 과거 적재 설계 전체가 여기 걸려 있다 |
| **`numOfRows` 최대값** | 10,000 이면 날짜당 1회, 현재 클라이언트 상수는 `PAGE_SIZE = 1000` 이라 날짜당 3회 |
| **응답에 상장폐지 종목이 그 시점 기준으로 포함되는가** | "날짜별 적재가 시점 유니버스를 공짜로 준다"는 판단의 전제다 |
| **토스증권 rate limit** | 2단 폴링 주기와 분봉 적재 소요 시간을 정하는 값 |
| **토스증권 1분봉 보관 기간** | **국내 단타 백테스트의 상한을 정한다.** 3개월만 주면 그만큼이 한계이고, 그 경우 KIS 모의계좌로 갈아탄다 |
| data.go.kr 금융위 API 의 정확한 서비스명·검색어 | 포털 검색 UI 를 직접 열어보지 못했다(도구 제약) |
| data.go.kr·OpenDART 의 승인 소요 시간(즉시/수동) | 이슈 #230 조사 범위 밖 — "확인 못 한 것" 목록에 있음 |
| OpenDART FAQ 의 상업이용 허용 문구 원문 | 이슈 #230 이 "FAQ 가 명시"라고만 기록, 원문 링크 없음 |
| Alpaca 가입·키 발급 화면의 정확한 메뉴 명칭 | 이 레포에 통합 이력이 없어 실사용 근거가 없다 |

이 표는 사람이 실제로 가입을 진행하면서 하나씩 지우면 된다 — 지워질 때마다 이 문서에 반영해
다음 사람은 ⚠ 없이 그대로 따라가게 한다.
