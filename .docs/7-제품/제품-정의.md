# 제품 정의 — trading-lab (status: draft)
> 제품의 단일 진실 원천. [prd](../specs/prd.md)(2026-07-28)를 출발점으로 [현황-감사](현황-감사.md)·[경쟁-분석](경쟁-분석.md)으로 검증·수정한 것이다. confirmed 되면 충돌 문서에 정본 콜아웃을 달고, 이후 Cycle 1~10 의 모든 선별·판정 기준이 된다.

## 1. 한 문장 정의

**국내·미국 주식으로 규칙 기반 매매를 하고 싶은 개인이, 자기 컴퓨터에서, AI 와 대화해 읽을 수 있는 전략을 만들고 → 한국 시장의 실제 거래 조건(비용·호가단위·가격제한폭·유동성)까지 반영해 검증하고 → 검증을 통과한 것만 모의로 굴려 그 결과가 화면에 꽉 차게 보는, 안전 계단이 구조로 강제된 셀프호스트 AI 트레이딩 플랫폼.**

**차별화 축**(남과 다른 것)은 둘이다 — 경쟁-분석 §3 이 근거다:

1. **검증의 현실성** — 비용 3종만으로 수익률 3.7~8.2p 차이·부호 반전이 실측됐다. 미반영 제약(호가단위·가격제한폭·유동성)까지 넣은 백테스트·모의 체결은 어떤 오픈소스에도 없다
2. **안전 계단** — 주문 경로는 코드 레벨에서 닫혀 있고(TRADING_LIVE_ENABLED), 검증을 통과하지 않은 전략은 다음 계단으로 못 올라간다. 제품이 대신 판정하지 않되, 계단을 건너뛰는 길을 만들지 않는다

### 1.1 뼈대 기능 — 차별화와 무관하게 반드시 잘해야 하는 것 (리드 지시 2026-08-19)

QuantDinger 가 보여준 핵심 기능은 **남도 한다는 이유로 뺄 수 없다** — 이 제품이 성립하려면 있어야 하는 뼈대이고, 우리 방식(전략 규약·출처 표시·디자인 시스템·안전 계단)으로 잘 만들어야 한다. AI 는 이 뼈대의 전면에 선다.

| 뼈대 | QuantDinger 방식 | 우리 방식 |
|---|---|---|
| **AI 가 전략을 만든다** | Monaco 편집기에 Python 을 써 주고 사람이 읽고·고치고·저장 | 대화가 **읽을 수 있는 전략 파일**(우리 전략 규약 `strategies/*.py`)을 만들고, 사람이 읽고·고치고·저장한다. 폼 채움(M2)에서 코드 산출로 확장 — 2026-08-18 결정 로그가 미뤄 둔 것을 확정. 경계 문구("지표는 신호만, 리스크·비용은 실행 설정의 몫")를 편집 화면 안에 둔다 |
| **결과가 화면에 꽉 찬다** | 자산·승률·손익비·MDD 카드, 손익 격자, 드로다운 곡선, 시간대 분포, 캔들 위 매매 마커, 「돌고 있음」 목록 | 같은 밀도를 우리 격자·곡선·마커로 — 단 **채우는 구조이지 채운 척이 아니다**(장난감 숫자 금지, 모든 값에 출처 표시 유지) |
| **멀티 LLM 제공자** | OpenRouter·OpenAI 호환·Google·DeepSeek 등 | 제공자 선택 + 키 화면 입력 + 무슨 모델이 답했는지 표시 (#226·#249 백로그가 이 자리) |
| **Agent Gateway / MCP** | `/api/agent/v1` + Claude Code·Cursor 호환 MCP | 우리 플랫폼 기능(시세·봇·백테스트)을 MCP 로 노출 — MCP 서비스 군 인프라 보유. 브로커 **릴레이**는 여전히 Non-goal(§4-3)이고, 노출 대상은 우리 제품 기능이다 |
| **모의 → 실거래 → 모니터링 스택** | paper/live execution + monitoring | 자체 시뮬레이터(의사결정-로그 §3) → 검증 통과만 승격 → 실주문은 범위 밖이되 계단 구조 유지 |

## 3. 대상 사용자

| 세그먼트 | 현재 대안 | 그 대안의 불편 |
|---|---|---|
| **S1. 규칙은 있는데 코딩은 없는 직장인 투자자** — "5% 빠지면 사고 싶다" 수준의 규칙 보유 | 엑셀 수기 검증, 유튜브 감각, 증권사 앱 조건 검색 | 규칙을 검증할 방법이 없다. 비용·체결을 무시한 "그럴듯한" 수익 곡선에 속는다 |
| **S2. 파이썬은 쓰지만 퀀트는 처음인 개발자** | KIS 공식 샘플 + Lean 백테스터 조립, 커뮤니티 래퍼 | 조각을 직접 조립해야 하고, 백테스터의 한국 현실성이 미공개라 결과를 믿을 수 없다. 화면·봇 수명주기가 없다 |
| **S3. 백테스트 결과를 의심하는 경험 트레이더** | Backtrader·VectorBT 자작, 반자동 매매 | KRX 미시구조(호가단위·가격제한폭·유동성)가 없어 실전과 어긋난다 — 그 어긋남의 크기를 잴 수단조차 없다 |

## 4. 하지 않을 것 (Non-goals)

경쟁 제품이 하지만 우리는 안 하는 것에 ★.

1. ★ **크립토·파생상품** — Freqtrade·Jesse 의 영역. 국내·미국 **주식**까지다
2. ★ **범용 백테스트 엔진/라이브러리化** — Nautilus·VectorBT 의 영역. 우리 엔진은 이 제품 전용이고 pip 패키지로 내지 않는다
3. ★ **브로커 범용 래퍼·MCP 릴레이 공개** — KIS·키움·토스 전부 커뮤니티가 이미 겹겹이 만들었다. 토스 어댑터는 우리 파이프라인의 입구로만 존재한다
4. **전략 마켓플레이스·매매 신호 배포·수익률 공개 리더보드** — 규제 검토 대상 (운영 규약 C절, 승인 없이 금지)
5. **실주문 전면 자동화** — 검증 없는 전략으로 실계좌를 굴리는 길을 만들지 않는다. 실주문 자체가 1차 범위 밖이며, 열 때도 계단(검증 통과→모의→승인)을 강제한다
6. **호스팅 SaaS 운영** — 로컬판 완성이 먼저. 모드 분리만 유지한다
7. **모바일 전용 화면** — 데스크톱 터미널이 대상 (터치 표적 등 반응형 하한은 유지)
8. **여러 증권사 계좌 통합 조회(마이데이터)** — 개인이 취득할 수 없는 자격
9. ★ **HFT·틱 단위 초단타** — 일봉·분봉 스윙까지다. 나노초 정밀도는 Nautilus 의 영역
10. **자체 모델 학습(ML 팩터 마이닝)** — Qlib·RD-Agent 의 영역. LLM 은 전략 생성·해석 보조로만

## 5. 핵심 워크플로 (시작 → 끝)

| # | 워크플로 | 시작 | 끝 | 상태 |
|---|---|---|---|:---:|
| W1 | **받아서 띄운다** | `git clone` | 문서만으로 로그인·실험대 도달, 키 없이도 기동 | 완료 (SC-001) |
| W2 | **데이터를 채운다** | 설정 화면에서 키 입력(또는 .env) | 적재 실행 → 차트 캔들 = 소스 값 일치, 이력·실패가 화면에 | 샘플 완료 · **토스 실측 대기(IP)** |
| W3 | **AI 와 전략·봇을 만든다** | 실험대 「봇 만들기」(대화 또는 폼) | 저장된 봇의 조건이 폼에 그대로 보임. **확장(§1.1)**: 대화가 전략 규약 파일을 만들고 사람이 읽고·고치고·저장 | 폼 채움 완료 · **코드 산출 확장이 백로그** |
| W4 | **과거로 검증한다** | 봇 선택 → 격자 실행 | **현실 조건(비용 → 이후 호가단위·가격제한폭·유동성) 반영 성과**가 격자·곡선으로, 미반영 대비 격차가 함께 표시 | 엔진·격자 완료 · **현실성 확장이 다음 베팅** |
| W5 | **모의로 굴리고 결과를 본다** | 검증 통과 봇을 시뮬레이터에 올림 | 장중 시그널·모의 체결 기록 → **성과 카드·손익 격자·드로다운 곡선·캔들 마커·「돌고 있음」 목록이 꽉 찬 화면**(§1.1) | **미구현** (자체 시뮬레이터 — 의사결정-로그 §3) |

> W4→W5 는 계단이다: 검증을 통과하지 않은 봇은 W5 로 못 올라간다. W5→실주문은 이 문서 범위 밖이고, 열더라도 같은 계단 구조를 강제한다.

## 6. 성공 기준 (검증 가능)

prd SC-001~006 유지 (전부 실측 경로 있음 — 현황-감사 §3). 추가:

- **SC-007**: 백테스트 결과가 「비용·제약 미반영 vs 반영」 격차를 수치로 나란히 보여준다 — 가설 A 실측(3.7~8.2p·부호 반전)의 제품화
- **SC-008**: 주문 계열 호출은 `TRADING_LIVE_ENABLED` 정확 일치 없이 코드 레벨에서 열리지 않는다 — 그물(19단언)이 상시 증명
- **SC-009**: 검증(백테스트) 이력이 없는 봇은 모의 운용에 올릴 수 없다 — W5 구현 시 그물로 잠근다
- **SC-010**: KRX 제약(호가단위·가격제한폭·거래세 구분) 반영 백테스트가 실체결 대비 오차를 줄인다 — 모의 운용 기록과 백테스트 재현의 대조로 측정 (W5 이후)
- **SC-011**: AI 대화로 만든 전략이 **읽을 수 있는 전략 규약 파일**로 저장되고, 사람이 그 파일을 고쳐 저장하면 그대로 반영된다 (§1.1 첫 뼈대)
- **counter-metric**: 기능이 늘어도 W1(클론→화면)의 단계 수가 늘지 않는다 · 화면의 모든 숫자가 출처 표시를 유지한다 (SC-005 승계)

## 7. 1차 범위와 확장

**1차 범위 = 국내(KRX: KOSPI·KOSDAQ·KONEX) + 미국(NASDAQ·NYSE·AMEX) 주식, 브로커·시세는 토스증권 Open API 단일** (리드 지시 2026-08-19 — 토스가 두 시장을 한 API 로 커버하므로 미국을 빼지 않는다). 단 **미시구조 정밀도는 순서가 있다**: 호가단위·가격제한폭·거래세 같은 시장 제약은 KRX 부터 채우고, 미국은 기본 비용 모델(수수료·슬리피지·SEC fee)에서 시작해 따라온다.

확장 가능성(구현하지 않음, 구조만 유지): 보조 시세 소스(alpaca·sec 어댑터 실재 — capability 로 이미 갈려 있음) · KIS(실주문 승격 직전 교차 검증용 — 의사결정-로그 §3) · 호스팅 모드(키 화면·주문 가드가 이미 모드 축을 탄다).

## 8. 0.2 판단의 반영과 자기 검토

- **계속 개발한다** (현황-감사 §7.5) — 재구성 아님. 확장 축은 백테스트 현실성·시뮬레이터·AI 전략 산출이고, 전부 기존 엔진·파이프라인·전략 규약 위에 얹는다
- **초안 대비 수정 이력 (리드 지시 2026-08-19)**: 초안은 "AI 가 차별화가 못 된다"는 경쟁-분석을 근거로 AI 를 정의 문장에서 빼고 미국을 1차 범위에서 뺐다. 리드가 둘 다 기각 — **차별화(남과 다른 것)와 뼈대(같아도 잘해야 하는 것)는 다른 질문**이고, QuantDinger 의 핵심 기능(AI 전략 생성·꽉 찬 결과 화면·멀티 제공자·MCP·모의 운용 스택)은 뼈대로서 전면에 선다(§1.1). 미국은 토스가 단일 API 로 커버하므로 유지한다
- **경쟁-분석과의 정합**: 차별화 축 둘(현실성·안전 계단)은 경쟁-분석 §3 그대로다. AI 뼈대는 "잘하는 것"의 문제이지 "남과 다른 것"의 주장으로 쓰지 않는다 — 모순 없음
