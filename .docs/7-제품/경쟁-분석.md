# 경쟁 분석 — 트레이딩 봇 플랫폼 지형과 세 가설의 판정 (Cycle 0)
> 2026-08-19 기준 공개 저장소·공식 문서로 확인한 것만 적는다. 결론을 정해 놓고 정당화하지 않는다 — 가설 C 는 부분 반증됐고 그대로 남긴다. 이 레포의 제품 방향 판단 전용.

## 2. 세 가설의 판정

### 가설 A — 기존 오픈소스는 국내 시장 고유 제약을 제대로 다루지 않는다 → **참**

- 범용 엔진(Freqtrade·Jesse·Nautilus·Backtrader·VectorBT·LEAN·Qlib)은 KRX 를 지원하지 않거나 일반화된 체결 모델만 갖는다. **호가 단위 구간·가격제한폭·동시호가·VI·거래정지·증권거래세(코스피/코스닥 구분)·거래대금 대비 체결 물량**을 다루는 오픈소스를 찾지 못했다
- 유일한 KRX 백테스터인 KIS 공식도 Lean 기본값으로 추정되며 한국 특화 조정을 문서화하지 않았다 (미공개 = 미확인으로 기록)
- **우리 실측이 이 가설의 무게를 보여준다** (0.0.3-4, 샘플 데이터): 현실 회전(14~44건/7.5개월)에서 **명시 비용 3종(수수료·슬리피지·거래세)만으로 수익률 3.7~8.2p 차이, 부호 반전 1건(+1.05%→-4.79%), 이익 69% 증발 1건**. 미반영 제약(호가단위·가격제한폭·유동성)까지 넣으면 격차는 더 벌어진다 — 그리고 **그 제약은 우리 엔진에도 아직 없다** (현황-감사 §7.4). 실데이터 재실측은 자격(IP 등록) 완성 뒤

### 가설 B — 토스증권 Open API 에 공식 sandbox 가 없다 → **참** (공식 문서로 확인)

- `openapi.tossinvest.com/openapi-docs` 전체에서 sandbox/모의투자 언급 없음 (2026-08-19 확인). 베이스 URL 하나뿐
- 따라서 paper trading 은 자체 구현 대상 — **아키텍처 영향이 확정**됐고 방향(자체 체결 시뮬레이터, KIS 모의는 교차 검증용)은 의사결정-로그 §3

### 가설 C — 「국내 주식 + AI Agent + 신뢰할 백테스트」 동시 만족 오픈소스가 없다 → **부분 반증**

**반증 후보: KIS open-trading-api 생태계.** 전략빌더(80개 지표) + Lean 백테스터 + 모의투자 + MCP + AI 확장(자연어로 설계→백테스트→주문)까지 — 세 요소를 **조각으로는 전부** 갖췄다. 정직하게 적으면, "아무도 없다"는 문장은 이제 거짓이다.

다만 **동시 만족의 "동시"가 성립하지 않는 지점**이 남는다:

1. **제품이 아니라 도구 모음이다** — 셀프호스트 화면·워크스페이스·봇 수명주기(만들고→검증하고→굴리고 성과 비교)가 없다. 백테스트는 Docker 로 Lean 을 돌려 HTML 리포트를 뽑는 방식
2. **백테스트의 한국 현실성이 미공개다** — Lean 기본 체결 모델에 KRX 미시구조 조정이 있는지 문서가 말하지 않는다
3. **브로커 락인** — KIS 계정 전제. 토스 사용자는 대상 밖
4. **라이선스 미명시** — 오픈소스로서의 재사용 조건이 불확실
5. **안전 계단이 없다** — 검증 없는 전략의 실주문을 구조로 막는 장치(우리의 TRADING_LIVE_ENABLED 코드 레벨 차단·검증 통과 승격 같은)는 어디에도 없다

## 3. 결론

**이미 잘 해결됨 (만들면 안 되는 것)**
- 크립토 봇 루프(Freqtrade) · 범용 고성능 백테스트 엔진(Nautilus·VectorBT) · 팩터 리서치(Qlib) — 이 축에서 경쟁하지 않는다
- **브로커 API 래퍼·MCP 릴레이** — KIS·키움·토스 전부 커뮤니티가 이미 겹겹이 만들었다. 우리 토스 어댑터는 **우리 파이프라인의 입구**로만 존재하고, 범용 래퍼·릴레이로 발전시키지 않는다

**부분적으로만 해결됨**
- KR 브로커 + 백테스트 + AI (KIS 공식 — 조각은 다 있으나 제품 아님, 현실성 미공개, 락인)
- KRX 데이터 접근 (pykrx — 데이터만)

**아무도 제대로 하지 않음**
1. **KRX 미시구조를 반영한 백테스트·모의 체결** — 호가단위·가격제한폭·동시호가·거래세 구분·유동성 상한. 실측으로 격차를 증명했다
2. **셀프호스트 제품형 통합** — 화면·봇 수명주기·데이터 출처 표시·워크스페이스가 한 몸인 것 (QuantDinger 가 이 형태이나 KRX 없음 + 프론트 상업 제한)
3. **검증 → 승격의 안전 계단을 구조로 강제** — 코드 레벨 주문 차단, 백테스트 통과 전략만 승격

**만들 이유가 있는가 — 있다.** ①·②·③ 의 교집합이 비어 있고, 우리는 ③(주문 차단 가드)과 ②의 골조(터미널·봇·출처 표시)를 이미 갖고 있으며 ①의 격차를 실측(3.7~8.2p·부호 반전)으로 증명했다. 단, 조건이 붙는다: **KIS 공식 생태계가 조각을 제품으로 통합하는 순간 2번 축의 시간 우위는 사라진다** — 차별화의 무게는 1번(현실성)과 3번(안전 계단)에 두어야 한다.
