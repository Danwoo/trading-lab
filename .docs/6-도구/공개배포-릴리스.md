# 공개 트리 이관 — 이사에 한 번 쓰는 도구

> 개발 자리를 공개 레포(`trading-lab`)로 옮기고 **거기서 개발을 계속한다.** 이 문서는 그 이사에서
> **트리를 밀어 넣는 한 걸음**(`release_public.py`)이 무엇을 확인하고 무엇을 미는지, 그리고 무엇을
> 못 막는지를 설명한다. 절차의 정본은 **스크립트**이고, 이사 전체의 순서는
> [공개 레포 이사 런북](공개레포-이사.md) 이 정본이다.

> **이 도구는 한 번 돈다.** 이사 뒤의 「릴리스」는 없다 — 그다음 변경은 공개 레포의 보통 커밋·PR 이고,
> 이 스크립트를 다시 돌릴 자리는 없다 (§2 「다시 돌리면 무슨 일이 나는가」).

| | |
|---|---|
| 실행 | `python3 scripts/release_public.py --remote <공개레포 URL>` |
| 내용 게이트 | `scripts/verify_public_release_tree.py` (이관 직전 + 매 PR CI) |
| 기본 동작 | **드라이런** — `--execute` 없이는 아무것도 밀지 않는다 |

---

## 0. 왜 이렇게 하나

이 개발 저장소의 git 히스토리에는 **출처 불명 제3자 이미지 4개**가 남아 있다. PR #359 가 작업
트리에서는 지웠지만, 히스토리를 포함해 공개하면 루트의 MIT `LICENSE` 와 함께 **그대로
재배포**된다 (#360).

히스토리 재작성(`git filter-repo` + force push)은 택하지 않았다 — 모든 커밋 해시가 바뀌어
열린 PR·클론·이슈의 커밋 참조가 전부 깨진다. 대신 **새 공개 레포에 현재 트리만 내보내고, 개발
자리를 거기로 옮긴다.** 그러면 그 자산은 애초에 공개본에 존재하지 않아 **노출면이 구조적으로
닫힌다.**

대가는 하나다: **이사 이전의 개발 이력이 공개본에 없다.** 그 이력(2026-08-07 기준 닫힌 이슈 229건·PR 200건·커밋)은
보관용으로 남는 비공개 레포에 그대로 보존된다. **이사 이후의 개발 이력은 전부 공개된다** —
커밋·이슈·PR·실패한 시도까지. 그것이 이 모델의 감수 사항이다 (`CONTEXT.md` 결정 로그 2026-08-07).

## 1. 무엇이 나가나

**현재 트리 전부.** 리드 결정(2026-08-05)으로 제외 대상은 없다 — `.docs/`·`.claude/`·
`CONTEXT.md`·`AGENTS.md`·CI 워크플로까지 전부 나간다.

내보내기는 **오직 `git archive <커밋>`** 으로 만든다. 이 명령은 그 커밋의 **트리만** 뱉는다:

- `.git` 이 담기지 않는다 → **히스토리가 나갈 경로 자체가 없다**
- gitignore 대상이 담기지 않는다 → `.env` 실파일·빌드 산출물·`node_modules` 는 원래 안 나간다
- 워킹트리의 미커밋 변경이 담기지 않는다 → 「지금 로컬에 있는 것」이 아니라 「커밋된 것」이 나간다

스크립트에는 `push --mirror`·`--force`·`--tags`·`--all` 이 **한 줄도 없고**, 개발 레포의
`.git` 을 공개 원격에 연결하는 경로도 없다 (공개 원격은 별도 임시 클론에만 붙는다).

> **주의 — 이것은 하드 게이트가 아니다.** 사람이 손으로 `git push --mirror` 를 치면 막을 것이
> 없다. 보호의 실체는 「정상 경로가 명령 한 줄이라 그걸 안 쓸 이유가 없다」와 이 문서뿐이다.

## 2. 한 번만 돈다 — 그런데 왜 append 로 짜여 있나

**이 스크립트는 빈 공개 레포 위에 커밋 하나를 얹는다.** 그 커밋이 공개본의 초기 커밋이고,
그 뒤로는 사람과 에이전트가 공개 레포에 평범하게 커밋한다. 이 도구가 다시 돌 자리는 없다.

그런데 구현은 **「목적지의 기본 브랜치 위에 append」** 로 짜여 있다 — force push 가 한 줄도 없고,
공개본이 앞서 나갔으면 그 위에 쌓는다. 1회용인데 그 모양인 이유는 셋이다:

1. **첫 push 자체가 append 다.** 빈 레포에 커밋 하나를 얹는 것은 「직전이 없는 append」이지
   특별한 경로가 아니다. 1회용이라고 다른 코드를 쓸 이유가 없다.
2. **재실행 안전성이 이사 당일의 복구 경로다.** 드라이런 → 실행 사이에 무엇이 어긋나 중간에
   멈춰도, 같은 명령을 다시 돌리면 된다. 내용이 같으면 **빈 커밋을 만들지 않고** 끝낸다(멱등).
3. **force push 가 없다는 사실 자체가 방어다.** 목적지에 예상 못 한 커밋이 있으면
   non-fast-forward 로 **실패한다**(fail-closed) — 그 상황에서 조용히 덮어쓰는 것보다 낫다.

**어느 브랜치에 얹는지는 목적지가 정한다 (#410).** 스크립트가 `main` 을 박아 쓰지 않고 공개
레포의 **실제 기본 브랜치**를 조회해, 비교 기준과 push 대상 양쪽에 같은 것을 쓴다. 판정이
불가능하면(원격 HEAD 가 없거나 실재하지 않는 브랜치를 가리키면) 추측하지 않고 **멈춘다** —
그때는 `--branch` 로 사람이 명시한다.

> **출력 문구는 아직 「릴리스」다.** `--branch` 도움말·매니페스트의 「첫 릴리스 … 파일 N개」·
> 「릴리스 커밋」 같은 표기가 그대로 남아 있다 — 이사 직전에 이 스크립트의 코드를 건드리지
> 않기 위해서다. 읽을 때는 전부 **이 1회 이관**을 가리킨다.

커밋 메시지에는 출처 개발 커밋을 `Source-Commit:` 트레일러로 적는다. 공개본의 초기 커밋만 보고도
**「이 스냅샷이 개발 레포의 어느 커밋인지」**를 알 수 있으면서, 개발 히스토리는 한 커밋도
넘어가지 않는다.

### 기여는 공개 레포에서 직접 받는다

개발 자리가 공개 레포로 옮겨가므로 **외부 기여를 그대로 받으면 된다** — 공개 레포에 온 이슈·PR 이
곧 이 프로젝트의 이슈·PR 이다. 받는 자리와 로컬 기동·라이선스·API 키 전제는 루트
[`README.md`](../../README.md) 의 「기여」 절이 안내한다.

> **다시 돌리면 무슨 일이 나는가.** 이 스크립트는 목적지 워킹트리의 추적 파일을 전부 지우고
> 개발 트리로 교체한다. 그래서 이사가 끝난 뒤 이것을 다시 돌리면 **공개 레포에 쌓인 커밋의
> 내용이 개발 트리로 덮인다**(커밋 자체는 조상으로 남는다). 이사 이후에는 쓰지 마라 —
> 트리를 옮기는 도구이지 동기화 도구가 아니다.

## 3. 무엇을 확인하고 미는가

스크립트가 순서대로 검사하고, **하나라도 실패하면 멈춘다**(fail-closed).

| # | 검사 | 실패 시 의미 |
|---|---|---|
| 0 | **원격이 개발 레포가 아닌가** (아래 §3.1) | `--remote` 가 이 레포 자신을 가리킨다 |
| 1 | 워킹트리 청결 | 「보고 있는 것」과 「나가는 것」이 다른 상태에서 확인 버튼을 누르지 않게 |
| 2 | 소스 커밋이 `origin/main` 에서 도달 가능 | 미머지 코드가 공개본으로 새는 경로 차단 |
| 3 | 고지 문서 신선도 | `THIRD-PARTY-NOTICES.md` 가 `frontend/package-lock.json` 보다 오래되면 의존성이 바뀐 뒤 고지가 안 따라온 것 |
| 4 | **내용 게이트** (아래 §4) | 공개본에 들어가면 안 되는 것이 있다 |
| 5 | **릴리스 브랜치 판정** (목적지의 기본 브랜치) | 판정 불가면 멈춘다 — 추측하면 엉뚱한 브랜치에 얹히고 매니페스트가 거짓이 된다 (#410) |
| 6 | 매니페스트·워크플로 보고 | 사람이 눈으로 확인하는 자리 |

### 3.1 원격 자기 지정 가드 (#406 ②)

`--remote` 에 **개발 레포 자신**을 주면 이관 커밋이 개발 레포 `main` 에 얹힌다. 로컬
non-bare 클론은 git 기본값(`receive.denyCurrentBranch=refuse`)이 막아 주지만, **bare
레포에는 그 보호가 없다** — 그리고 GitHub 는 bare 로 동작한다. 즉 클립보드 재사용이나
오타 한 글자로 조용히 성공한다 (#406 에서 재현했다).

두 층으로 막는다:

- **가드 A — 주소 대조** (클론 전). 정규화한 `--remote` 를 개발 레포의 경로·`.git`·**모든**
  remote URL 과 대조한다. 같은 곳을 가리키는 표기가 여럿이라 정규화가 필요하다:
  `https://…/x/y.git` · `https://…/x/y` · `git@…:x/y` · `ssh://…` · 대소문자 · 후행 슬래시 ·
  `file://` · 상대 경로 · 심링크 · 기본 포트 명시 · 유저인포 · 이중 슬래시 ·
  **FQDN 후행 점(`github.com.`)** · **`.GIT` 대문자 접미** · **퍼센트 인코딩 경로·호스트** ·
  **닷 세그먼트**(`/x/../owner/repo` · **선두** `/../owner/repo`·`/%2e%2e/…` ·
  **`.git` 접미 뒤** `…/repo.git/.`·`…/repo.git/x/..` — 선두 판은 상대 경로로 해소하던 탓에,
  접미 뒤 판은 `.git` 제거를 해소보다 먼저 하던 탓에 각각 3·4라운드까지 빠져나갔다)
  (뒤 넷은 PR #409 리뷰와 그 전수 조사가 뚫은 자리다 — 후행 점·퍼센트 인코딩·닷 세그먼트는
  읽기 전용 `ls-remote` 로 **같은 레포에 도달함**을 확인했다).
  **가드 A 가 표기 차이를 다 잡지는 못한다** — git 설정의 `insteadOf` 재작성, IDNA 매핑으로
  같은 호스트가 되는 유니코드 마침표, DNS·hosts·프록시로 같은 곳을 가리키게 만든 별개
  호스트명은 주소 문자열만으로 구분할 수 없다. 그 층은 가드 B 가 받는다.
- **가드 B — 내용 대조** (클론 후, 쓰기 전). 목적지가 **소스 커밋을 이미 갖고 있으면**
  거부한다. 주소만 보면 「개발 레포의 bare 미러를 다른 경로에 둔 것」을 못 잡는데, 재현이
  정확히 그 모양이었다. 이사 대상인 빈 공개 레포에는 개발 커밋이 한 개도 없다 — 이관 커밋은
  `Source-Commit:` 트레일러만 남기고 개발 히스토리를 조상으로 갖지 않기 때문이다.

**fail-closed**: 대조 대상이 0건이면 거부하고, 대조 건수를 매 실행에 출력한다.

게이트 스크립트를 찾지 못하면 **이관을 시작하지 않는다** — 게이트 없이 밀지 않는다.

## 4. 내용 게이트 — `verify_public_release_tree.py`

무엇을 막는지·왜 그렇게 짰는지·**무엇을 못 막는지**는 그 스크립트의 독스트링이 정본이다.
요약:

- **제거 대상 blob 재유입** — #359 가 지운 이미지 4개의 blob 해시를 못박고 대조한다.
  파일 이름·경로를 바꿔도 내용이 같으면 blob 해시가 같아서 잡힌다.
- **자격증명** — `.env` 실파일(`.env.example` 은 예외)·개인키·인증서 등 경로 규칙 + 텍스트
  안의 고신호 시크릿 패턴(PEM 개인키 헤더·`ghp_`·`AKIA…` 등).
- **출처 미등록 자산** — **UTF-8 로 읽히지 않는 모든 파일**(= 바이너리)과 자산 확장자 파일은
  `ASSET_ALLOWLIST` 에 **경로 + 내용 해시 + 출처**가 등록돼 있어야 한다. 확장자가 아니라
  「바이너리인가」를 기준으로 삼는 이유: `.png` 를 `.dat` 로 바꿔 넣는 경로를 확장자
  목록으로는 못 막는다. #360 의 재발 방지는 「이 4개」가 아니라 **「출처를 모르는 바이너리가
  공개본에 들어가는 것」이라는 클래스**를 막는 것이다.
- **필수 파일** — `LICENSE`·`THIRD-PARTY-NOTICES.md`.
- **텍스트 파일에 인라인된 자산** (#406 ①) — 위 세 규칙은 **파일**을 단위로 보므로, 자산을
  base64 로 바꿔 `.css`·`.ts`·`.json`·`.md` 의 `data:` URI 에 넣으면 그 파일이 「텍스트이고
  자산 확장자가 아니다」로 판정돼 **검사 범위에서 통째로 빠졌다.** 이제 텍스트 파일 안에서
  자산으로 디코드되는 조각(`data:` URI · 자산 매직 넘버로 시작하는 base64 런)을 꺼내 **같은
  두 규칙**을 그 조각에 적용한다. 선언된 mime 은 믿지 않고 **디코드된 바이트를 스니핑**한다
  (`data:text/plain;base64,<PNG>` 로 라벨만 바꾸는 우회 때문).
  - **제거 대상 blob 재유입에는 크기 문턱이 없다.** 정확 해시 일치라 **해시까지 도달한
    조각**에 대해서는 오탐도 미탐도 없다. 다만 **조각이 해시까지 도달하는 것 자체는 보장되지
    않는다** — 탐지기가 payload 를 원본 그대로 꺼내지 못하면 해시는 계산조차 되지 않는다.
    「정확 해시니까 안 뚫린다」로 읽지 마라. 실제 강도는 **탐지기가 어디까지 보느냐**이고,
    그 경계는 §7 이 정본이다.
  - **`data:` URI 는 브라우저와 같은 순서로 푼다** (PR #409 리뷰). 공백을 배제하던 종전
    정규식은 **MIME 표준 76컬럼 줄바꿈 한 줄로 두 규칙이 전부 뚫렸다** — 브라우저(WHATWG
    `data:` URL 처리)는 그 공백을 지우고 원본을 되살린다. 페이로드 안의 공백뿐 아니라
    **퍼센트로 적은 공백(`%0A`·`%20`)** 과 **`;base64,` 표시·마임 구간·스킴 키워드
    (`da\nta:`)의 공백**까지 같은 규칙으로 처리한다.
  - **메타데이터 구간에 길이 상한이 없다** (PR #409 kimi CI 리뷰). 종전 200자 상한은 주석에
    성능 근거만 달려 있었지만 실제로는 **미탐**이었다 — 파라미터를 그만큼 패딩하면 탐지가
    통째로 빠져나갔고, 매직 넘버가 없는 포맷(SVG·gzip 등)은 받아 줄 보조 탐지기도 없었다.
    지금은 `;base64,` 표시를 먼저 잡고 메타데이터를 역방향으로 읽어 **상한 없이도 비용이
    선형**이다 (실측: 트리 전수 스캔이 오히려 빨라졌다).
  - **벡터 판정은 마커의 위치를 보지 않는다** (PR #409 3라운드). 이 판정은 두 번 고쳐졌고
    **두 번 다 자산의 시작점을 알아맞히는 방식이라** 뚫렸다 — 선두 512 B **창**은 루트 앞
    주석 한 덩어리로 넘어갔고, 그 처방인 **프롤로그 건너뛰기**는 계산한 오프셋에서 `<` 를
    요구해 **선두 바이트 하나로 통째로 죽었다**(UTF-8 BOM·NUL·NEL U+0085·NBSP·그 밖의 C0
    제어문자 — 진입점이 파이썬 기본 ASCII 공백만 벗기는 `lstrip()` 이었다). 루트 앞에 올 수
    있는 바이트를 열거해 메우는 길은 닫히지 않으므로, 지금은 **마커가 payload 안에 있으면
    벡터로 본다** — 상수가 없어 「그만큼 패딩하면 다시 뚫린다」가 성립하지 않는다.
    **UTF-16·UTF-32 로 인코딩된 XML**(ASCII 글자 사이에 NUL 이 낀다)은 NUL 을 지운 판에서도
    같은 마커를 봐서 함께 받는다. 네임스페이스 접두(`<n:svg>`)와 퍼센트 인코딩하지 않은
    원문 SVG 표기도 함께 받는다. **대가는 오탐이다** — `<svg` 를 **설명만** 하는 산문을
    인라인하면 벡터로 잡힌다 (실측: 트리 전 파일을 통째로 인라인한 최악 가정에서 3→14파일,
    늘어난 11 중 8은 진짜 JSX 아트워크. **실제 트리에서 새로 생기는 위반은 0건**).
  - **미등록 인라인 자산은 래스터만 1 KiB 이상**을 본다. 1x1 픽셀·스페이서까지 등록을
    요구하면 오차단이 잦아 사람이 게이트를 끄게 된다. **스니핑이 벡터(SVG)로 알아본 조각에는
    문턱이 없다** — 바이트 수와 시각적 식별성이 비례하지 않아(리뷰가 상표 로고를 511 B 로
    통과시켰다) 문턱의 근거가 벡터에는 성립하지 않는다. 이는 `.svg` **파일**을 크기 무관으로
    등록 대상으로 삼는 위 규칙과 같은 취급이다. 다만 **이 면제는 스니핑의 성공에 종속된다** —
    못 알아본 조각은 「바이너리(매직 미상)」로 떨어져 래스터 문턱을 다시 받는다 (실측: 68 B
    SVG 아이콘을 UTF-16 으로 인코딩한 138 B 판이 그 자리로 빠져나갔다. 그 계열은 위에서
    막았고, 남은 것은 §7). 정당하게 인라인해야 하면
    `INLINE_ASSET_ALLOWLIST` 에 **디코드 내용의 해시 + 출처**를 적는다
    (경로가 아니라 내용으로 등록한다 — 같은 조각이 여러 파일에 실릴 수 있다).

**fail-closed**: 스캔 파일이 하한 미만이면 실패한다. 등록부에 있는데 트리에 없는 낡은
등록도 실패한다(그 등록이 같은 경로로 들어올 다음 파일에 통과를 내주기 때문). 인라인 스캔
대상이 0건이거나 자산 매직 넘버 표가 비어도 실패한다. 검사한 파일 수·자산 수·대조한 금지
blob 수·인라인 스캔 건수를 항상 출력하므로, 초록이 「위반 없음」인지 「아무것도 안 봤음」인지
구분할 수 있다.

**이 게이트는 이사로 끝나지 않는다.** 같은 검사가 매 PR 에서 돈다
(`.github/workflows/repo-scans.yml` 의 `public-release-tree` 잡). 이사 전에는 「이관 날에 처음
아는 상황」을 없애는 장치였고, **이사 뒤에는 공개 레포에 들어가는 모든 변경을 막는 유일한
그물**이 된다 — 공개 레포에 머지된 것은 곧 공개된 것이라 회수가 불가능하기 때문이다.
같은 잡의 두 번째 단계(`scripts/test_public_release_gate.py`)는 **게이트가 무엇을 잡아야
하는지**를 케이스로 못박는다 — 트리 스캔만 두면 검사 규칙을 지워도 트리가 깨끗한 한
초록이기 때문이다 (#406).

### 새 이미지·폰트를 추가하려면

`ASSET_ALLOWLIST` 에 등록해야 CI 가 통과한다. 등록에는 **출처**를 적는다 — 적을 수 없으면
공개본에 넣지 않는다. 파일이 바뀌면 해시가 어긋나 실패하므로, 자산 교체는 반드시
등록 갱신을 동반한다.

### 출처 미검증 자산 (#361)

`frontend/public/logo.png`·`favicon.ico` 는 「코드로 생성」했다고 기록됐지만 생성 SVG·
래스터화 스크립트가 커밋되지 않아 **재현이 불가능**하다(#361). 이것을 이관 차단
사유로 삼지 **않는다** — 리드 결정은 「전부 넣는다」이고 #361 은 별도로 추적됐다. 대신
`verified=False` 로 등록해 **실행 출력에 「출처 미검증」으로 이름이 뜨고**, 내용 해시가
못박혀 있어 조용히 바뀌면 실패한다. 재현 경로가 커밋되면 해시를 갱신하고 `verified=True` 로 바꾼다.

## 5. CI 워크플로 — 공개본에서도 Actions 가 돈다

리드 결정에 따라 워크플로를 **제외하지 않는다.** 빌드·테스트 워크플로(`ci.yml`·
`frontend-ci.yml`·`repo-scans.yml`)는 공개본에서도 그대로 값이 있다. 다만 하네스 자동화
워크플로(`cross-review`·`plan-label*`·`board-status`·`merge-router`·`review-gate`·
`plan-check`·`orphaned-branch-scan`)는 **시크릿·라벨·프로젝트 보드·self-hosted 러너를
새 레포에 다시 붙이기 전까지** 실패하거나 아무 일도 하지 않는다. 다시 붙이는 절차는
[이사 런북 §5](공개레포-이사.md) 가 정본이다.

그래서 이관 스크립트가 워크플로별로 「시크릿 필요 / self-hosted 러너 / 쓰기 권한」을
표로 뽑아 보여준다. **공개 레포에서 Actions 를 어떻게 둘지는 사람이 정한다** — 후보는
① 그대로 두고 실패를 감수 ② 공개 레포 설정에서 Actions 를 끄거나 워크플로를 개별 비활성화
③ 세팅(러너·시크릿·변수)을 먼저 끝내고 켠다.

**보안 표면 확인 (2026-08-05 기준)**:

- `pull_request_target` 사용 **0건** — 포크 PR 이 시크릿·쓰기 토큰을 얻는 전형적 경로 없음
- self-hosted 러너를 쓰는 유일한 잡(`cross-review.yml` 의 `review`)에
  `head.repo.full_name == github.repository` 가드가 걸려 있어 **포크 PR 이 self-hosted
  러너에 도달하지 못한다**

이 사실이 바뀌면 이관 스크립트의 워크플로 보고 출력이 달라진다.

## 6. 실제 순서

```bash
# 0. 개발 레포를 최신으로
git fetch origin

# 1. 드라이런 — 무엇이 나갈지 전부 출력하고 아무것도 쓰지 않는다
python3 scripts/release_public.py --remote git@github.com:<owner>/<repo>.git

# 2. 출력 확인
#    · 「출처 미검증 자산」에 예상치 못한 것이 없는가
#    · 「내보내는 것」 목록에 나가면 안 되는 디렉터리가 없는가
#    · 「릴리스 브랜치」가 공개 레포의 기본 브랜치와 같은가
#    · 매니페스트가 「첫 릴리스 (<브랜치> 신규) — 초기 커밋에 파일 N개」로 나오는가
#      (「직전 릴리스 대비 …」로 나오면 목적지가 빈 레포가 아니다)

# 3. 실행
python3 scripts/release_public.py --remote git@github.com:<owner>/<repo>.git --execute
```

### ⚠ 게이트가 안 보는 것 — 여기는 사람이 봐야 한다

**게이트 초록은 「이 형태가 없다」가 아니라 「이 형태를 안 봤다」다.** 아래 두 가지는 게이트가
구조적으로 못 보므로 사람이 훑는 것이 유일한 방어다 (§7 참조). 이사는 트리 전체가 한 번에
나가므로 **트리 전수**로 본다.

```bash
# (가) 이스케이프로 접힌 인라인 자산 — 게이트는 이 형태를 못 잡는다 (§7 「소스 ≠ 런타임」)
#      `\n`·`&#10;` 로 접혀 있어도 브라우저에서는 원본 이미지로 복원된다.
#      **`data:` 만 보고 mime 모양은 요구하지 않는다** — `data:<슬래시 없는 쓰레기>;base64,`
#      처럼 mime 이 mime 처럼 안 생긴 형태도 브라우저는 되살리기 때문이다.
git grep -nIiE 'data:' -- '*.ts' '*.tsx' '*.js' '*.mjs' '*.py' '*.json' '*.css' '*.md' \
    '*.yml' '*.yaml' '*.toml'

# (나) 리터럴 <svg> 아트워크 — 역시 게이트 사정거리 밖이다 (네임스페이스 접두까지 본다)
git grep -nIiE '<([a-z_][a-z0-9_.-]*:)?svg[ >/]'
```

`data:` 나 긴 base64 덩어리가 보이면 **자산으로 의심하라.** 접혀 있든 아니든, 출처를
설명할 수 없으면 이관에서 빼거나 `INLINE_ASSET_ALLOWLIST` 에 출처를 적는다.

> **이사 뒤에는 같은 확인이 PR 디프에서 이뤄진다.** 공개 레포에서는 머지가 곧 공개이므로,
> 위 두 형태는 `git diff <base>..<head>` 에 같은 패턴을 걸어 리뷰가 본다.

옵션:

| 옵션 | 뜻 |
|---|---|
| `--remote` | **필수.** 기본값이 없다 — 「실수로 어딘가에」 가는 경로를 만들지 않는다 |
| `--name` | 공개 레포 이름 (기본 `trading-lab`) — 커밋 메시지·매니페스트 표기에 쓴다 |
| `--source-ref` | 내보낼 ref (기본 `origin/main`). `origin/main` 에서 도달 가능해야 한다 |
| `--branch` | 공개 레포의 릴리스 브랜치. **기본값 없음** — 목적지의 기본 브랜치를 조회한다 (#410). 판정 불가일 때만 사람이 적는다 |
| `--execute` | 실제로 push 한다. **없으면 드라이런** |

## 7. 이 절차가 못 막는 것

정직하게 적는다 — 여기 없는 보호를 있다고 읽지 않도록.

> **먼저 규칙 A 를 오해하지 마라.** 「제거 대상 blob 은 정확 해시로 잡으니 안전하다」는 절반만
> 맞다. **해시까지 도달한 조각**에 대해서는 정확하지만, **조각이 해시까지 도달하는 것 자체는
> 보장되지 않는다.** 탐지기가 payload 를 원본 그대로 꺼내지 못하면 해시는 계산조차 되지 않는다.
> 이 게이트의 실제 강도는 해시의 정확성이 아니라 **탐지기가 어디까지 보느냐**이고, 그 경계가
> 아래 목록이다.

- **㉮ 소스 텍스트 ≠ 런타임 값 — 언어 층 이스케이프로 접은 인라인 자산은 못 잡는다.**
  스캐너는 파일에 적힌 글자를 읽지만 브라우저는 **한 겹 더 디코딩된 값**을 읽는다.

  ```ts
  const LOGO = "data:image/png;base64,<76자>\n<76자>…";   // 소스에는 역슬래시+n
  ```

  소스에 실제 줄바꿈이 없어 게이트의 매치가 끊기지만, 번들러를 거치면 진짜 줄바꿈이 되고
  브라우저가 **원본 이미지를 그대로 복원한다.** 실측으로 24형태가 통과했고 그중 20형태는
  런타임 복원까지 확인했다 — JS/TS·JSON·Python·YAML·TOML 의 `\n` `\r` `\t` `\x0A` `\u000A`·
  줄 이음, HTML/JSX 문자 참조(`&#10;` `&#x0A;` `&NewLine;` `&Tab;`), CSS(`\A ` `\00000A`).
  **트리에 있는 텍스트 파일 유형이 전부 해당된다.**

  **왜 안 막나 (리드 결정):** 막으려면 게이트가 언어마다 다른 이스케이프 문법을 흉내내야
  하는데 그 싸움은 끝이 없고, 흉내가 어긋난 자리는 **조용한 미탐**이 되어 지금보다 나쁘다.
  대신 뚫린다는 사실을 적고, `scripts/test_public_release_gate.py` 의 「③ 문서화된 우회」
  케이스가 그 상태를 고정한다 — 누군가 막으면 그 테스트가 빨간불이 나서 이 문단을 갱신하게
  된다. **사람이 볼 자리는 §6 의 「게이트가 안 보는 것」 체크다.**

- **사람이 이 스크립트를 안 쓰는 것.** `git push --mirror` 를 손으로 치면 막을 것이 없다.
  강도는 **자동화 단**이지 하드 게이트가 아니다.
- **`--remote` 에 틀린 주소를 명시적으로 주는 것.** 단 **「개발 레포 자신」이라는 가장 비싼
  오타는 막는다** (§3.1). 못 막는 것은 **제3자의 엉뚱한 레포**다 — 우리가 아는 주소 목록
  밖이라 대조할 것이 없다(그쪽으로 밀려면 push 권한이 있어야 해서 실현 조건은 훨씬 좁다).
- **텍스트 안의 민감 정보.** 게이트는 고신호 형식(PEM·`ghp_`·`AKIA`)만 잡는다. 형식 없는
  비밀번호 문자열이나 `.env.example` 에 적힌 실제 값은 새어 나간다.
- **내용을 바꾼 제3자 자산.** blob 해시가 달라 금지 목록으로는 안 잡힌다 — 등록되지 않은
  바이너리를 전부 막는 규칙이 대신 받는다(사람이 출처를 적어야 통과).
- **텍스트로 옮겨 적은 제3자 코드.** 라이선스 스캐너·리뷰의 몫이다.
- **인라인 자산의 다른 인코딩.** hex·`\x` 이스케이프 배열·base85·바이트 리터럴 배열은 보지
  않는다. 문자열을 문턱(1 KiB) 아래에서 쪼개 이어 붙이는 것도 정적 스캔의 한계다. 어디까지
  보고 왜 거기서 끊었는지는 `verify_public_release_tree.py` 독스트링의 「못 막는 것」이 정본이다.
- **텍스트 파일에 리터럴로 쓴 `<svg>` 블록.** 탐지기는 `data:` URI 와 base64 런만 훑으므로
  `.tsx` 안에 JSX 로 그려 넣은 SVG 아트워크는 들어오지 않는다(현재 트리의 14파일 — 재현
  명령은 게이트 독스트링). 이 형태는 base64 와 달리 **디프에서 사람 눈에 그대로 보이므로**
  리뷰가 볼 자리다.
- **여는 따옴표가 없는데 공백은 담는 자리의 `data:` URI.** 게이트는 본문의 끝을 **컨테이너가
  닫히는 자리**(`"` · `'` · 백틱 · `(` 의 짝)로 정한다. 그래서 CSS·JS·JSX 의 표기는 마커를
  퍼센트로 적든 원문으로 적든, 공백이 리터럴이든 `%20` 이든 전부 잡는다. 반면 YAML·TOML 의
  평문 스칼라처럼 **따옴표 없이 공백을 담는** 자리는 컨테이너를 알아볼 수 없어 공백에서
  끊긴다 — 원문 `<svg` 가 콤마 바로 뒤에 오면 백스톱이 받지만 `%3c` 로 적으면 놓친다.
  표기별 탐지 여부는 `scripts/test_public_release_gate.py` 의 ①-f 가 축의 곱(컨테이너 ×
  인코딩 × 공백)으로 못박고, 경계와 이유는 게이트 독스트링 「못 막는 것」이 정본이다.

  > 종전 이 자리에는 「퍼센트 인코딩한 판은 프롤로그가 앞에 붙어도 잡힌다」는 **거짓 단정**이
  > 있었다. CSS 가 SVG 를 인라인하는 표준 관용구는 마커만 퍼센트로 적고 공백·따옴표는
  > 리터럴로 두어 그 전제(「인코딩하면 페이로드가 공백 없는 한 덩어리가 된다」)가 성립하지
  > 않았고, 그 표기가 **크기 무관으로 통과했다**. 지금은 잡는다.

- **SVG 마커를 언어 층으로 접은 것.** JSX 속성에 `&lt;svg …` 로 적으면 빌드가 엔티티를 풀어
  브라우저에는 `<svg` 가 되지만 소스에는 그 글자가 없다. 위의 이스케이프 계층과 같은 자리
  (리드 결정으로 열어 둔 층)이며, ①-f 가 「안 잡힘」으로 고정해 누가 막으면 빨간불이 난다.
- **스니핑이 못 알아본 1 KiB 미만 조각.** 문턱 면제는 「벡터로 **알아본** 것」에만 걸리므로,
  못 알아본 조각은 「바이너리(매직 미상)」로 떨어져 래스터 문턱을 다시 받는다. NUL 패딩
  계열(UTF-16·UTF-32)은 막았지만 EBCDIC·UTF-7 의 `+ADw-` 표기는 여전히 못 알아본다(실측).
  **그 둘을 브라우저가 되살리는지는 검증하지 않았다** — 되살린다면 진짜 우회이므로, 확인되면
  막을 자리로 올린다. 알아보지 못한 것을 면제할 수는 없으므로 이 종속성 자체는 구조적으로 남는다.
- **이미 공개된 것의 회수.** 한 번 push 된 것은 되돌릴 수 없다. 그래서 기본이 드라이런이다.
