> **왜 닫힌 이슈·PR 을 안 옮기나.** 리드 결정으로 비공개 레포가 **보관용으로 남는다**.
> 이력은 거기 그대로 있고, 옮기면 공개본에 「이미 끝난 일」 229건이 **번호만 새로 붙어** 쌓인다.
> PR 은 애초에 못 옮긴다 — 브랜치·커밋에 묶여 있는데 공개본에는 그 커밋이 하나도 없다.

## 1. 사전 조건 — 이사 전에 정리할 것

| 확인 | 왜 |
|---|---|
| 열린 PR 을 **전부 머지하거나 닫는다** | PR 은 못 옮긴다. 이사 후 이 레포에 머지하면 그 코드는 **보관용 레포에만** 남는다 — 공개 레포로 옮기려면 손으로 다시 올려야 한다 |
| `origin/main` 이 최신이고 워킹트리가 깨끗하다 | `release_public.py` 가 fail-closed 로 멈춘다 |
| **드라이런이 초록이다** (§3) | 이사 당일에 처음 알게 되는 상황을 없앤다 |
| 기여 경로가 README 에 있다 | 개발 자리가 공개 레포로 가므로 **이슈·PR 을 거기서 그대로 받는다.** 처음 온 사람이 어디에 무엇을 올릴지 모르면 기여가 시작되지 않는다 (루트 `README.md` 「기여」 절) |

```bash
gh pr list --state open          # 0건이어야 한다
git fetch origin && git status --porcelain   # 출력이 비어 있어야 한다
```

> ⚠ **「개발도 새 레포에서 계속한다」가 이 이사의 성격을 바꾼다.** 트리를 한 번 밀고 끝나는 것이
> 아니라, **작업 자리 자체가 옮겨간다.** 그래서 러너·변수·Orca 등록·로컬 클론까지 따라가야
> 하고(§5), 그것이 안 끝나면 새 레포에서 CI 가 돌지 않는다.

## 3. 단계 ① — 드라이런 (되돌릴 수 있다)

원격은 **로컬 bare 레포**로 둔다. 아직 GitHub 을 건드리지 않는다.

ⓐ 명령

```bash
mkdir -p /tmp/release-dryrun && git init --bare -b main /tmp/release-dryrun/trading-lab.git
python3 scripts/release_public.py --remote /tmp/release-dryrun/trading-lab.git
```

ⓑ 기대 출력 — 마지막 줄이 이것이다.

```
== 드라이런 종료 — 아무것도 쓰지 않았다 ==
```

ⓒ 확인 — 출력에서 **네 가지**를 눈으로 본다.

- `-- 3. 내용 게이트 --` 가 `위반 0건` 으로 끝나는가
- `⚠ 출처 미검증 자산` 목록에 **예상치 못한 것**이 없는가 (지금은 `favicon.ico`·`logo.png` 2건 — #361)
- `-- 4. 내보내는 것 --` 에 나가면 안 될 디렉터리가 없는가
- `-- 6. 목적지 --` 의 릴리스 브랜치가 기대한 이름인가

게이트가 안 보는 자리(언어 층으로 접은 인라인 자산·리터럴 `<svg>`)는 사람이 본다 —
명령은 [이관 도구 §6 「게이트가 안 보는 것」](공개배포-릴리스.md) 에 있다.

ⓓ 실패하면 — 되돌릴 것이 없다. 드라이런은 임시 디렉터리에서만 일어나고 지워진다.
**빨간불이면 거기가 이사가 막히는 자리다** — 걸린 파일을 고치고 다시 돌린다.
(`release_public.py`·`verify_public_release_tree.py` 를 고쳐 통과시키지 마라 — 게이트를 낮추는 것이다.)

## 4. 단계 ② ③ ④ — 실제 이사

### 4.1 ⛔ 단계 ② — 리드가 빈 공개 레포를 만든다

**직접 만든다. 스크립트도 에이전트도 만들지 않는다.**

- GitHub → **New repository**
- 이름 `trading-lab` · **Public**
- **`Add a README` · `.gitignore` · `license` 를 전부 끈다** — 완전히 빈 레포로 만든다.

> **왜 빈 레포여야 하나.** README 를 넣어도 이사는 성공하지만, 첫 릴리스 매니페스트가
> 「첫 릴리스 … 파일 1027개」가 아니라 「직전 릴리스 대비 추가 1026 · 변경 1」로 나온다
> (실측). 사람이 숫자를 보고 판단하는 자리인데 그 문장이 「이미 릴리스가 있었다」로 읽힌다.

**확인 지점 (다음 단계는 되돌릴 수 없다)**

```bash
gh repo view Danwoo/trading-lab --json name,visibility,defaultBranchRef,isEmpty
```

`"visibility":"PUBLIC"` 이고 `"isEmpty":true` 여야 한다.

ⓓ 되돌리기 — 이 시점까지는 레포를 지우면 원상복구된다 (Settings → Danger Zone → Delete).
단 **지운 이름은 곧바로 재사용할 수 없을 수 있다.**

### 4.2 ⛔ 단계 ③ — 트리 첫 릴리스

ⓐ 명령 — **드라이런을 한 번 더** 진짜 원격으로 돌리고, 출력을 확인한 뒤에만 `--execute` 를 붙인다.

```bash
python3 scripts/release_public.py --remote https://github.com/Danwoo/trading-lab.git
# 출력 확인 후:
python3 scripts/release_public.py --remote https://github.com/Danwoo/trading-lab.git --execute
```

ⓑ 기대 출력

```
== 릴리스 완료: trading-lab main <8자리 SHA> ==
```

ⓒ 확인

```bash
gh api repos/Danwoo/trading-lab/commits -q '.[].commit.message' | head -5
# → "release: trading-lab <날짜>" 한 건. Source-Commit: 트레일러가 개발 레포 SHA 와 같아야 한다.
git ls-remote https://github.com/Danwoo/trading-lab.git | wc -l   # ref 1~2개 (히스토리가 안 넘어갔다는 뜻)
```

ⓓ ⛔ **되돌릴 수 없다.** 공개된 것은 회수되지 않는다 — 레포를 지워도 그 사이 클론·크롤이
있었는지는 알 수 없다. 잘못 민 내용은 **공개 레포에서 다음 커밋으로 덮는다** (force push 금지 —
히스토리를 갈아엎으면 이미 클론한 사람의 `git pull` 이 깨진다). 지워야 할 것을 밀었다면 레포
삭제가 유일한 축소 수단이고, 그것도 완전하지 않다.

> **이관 스크립트를 다시 돌려 고치려 하지 마라.** 그것은 목적지 트리를 개발 트리로 통째로
> 교체하므로, 그 사이 공개 레포에 쌓인 것을 덮는다 ([이관 도구 §2](공개배포-릴리스.md)).

### 4.3 ⛔ 단계 ④ — 라벨·마일스톤·이슈 이관

ⓐ 명령

```bash
python3 scripts/migrate_public_repo_meta.py --target Danwoo/trading-lab            # 드라이런
python3 scripts/migrate_public_repo_meta.py --target Danwoo/trading-lab --execute  # 실행
```

ⓑ 기대 출력 — **모양**은 아래와 같다. 숫자는 실행 시점의 출처 레포를 따르므로
§0 표(2026-08-07 기준 라벨 35 · 마일스톤 6 · 열린 이슈 3)와 대조해 읽는다.

아래 블록은 **2026-08-05 드라이런의 실제 출력**이다 (그때는 열린 이슈가 5건이었다).

```
  · 출처 라벨 35개 — 생성 35 · 갱신 0 · 그대로 0
  · 출처 마일스톤 6개 — 생성 6 · 그대로 0
  · 출처 이슈 5건 — 생성 5 · 건너뜀 0
== 집계: 라벨 35 · 마일스톤 6 · 이슈 5 을 검사했다 ==
```

세 줄의 「출처 N개」가 **그 시점 §0 표와 같은지**가 확인 지점이다 — 다르면 표가 낡았거나
스크립트가 일부만 수집한 것이고, 어느 쪽인지 가르기 전에는 `--execute` 를 붙이지 않는다.

(새 레포에 GitHub 기본 라벨 9개가 있으면 `생성 26 · 그대로 9` 로 나온다 — 이름이 겹치는 것들이다.)

ⓒ 확인 — 기대값은 **드라이런이 출력한 「출처 N개」와 같은 수**다.

```bash
gh label list --repo Danwoo/trading-lab --limit 100 | wc -l          # 출처 라벨 수 이상
gh api 'repos/Danwoo/trading-lab/milestones?state=all' -q 'length'    # 출처 마일스톤 수
gh issue list --repo Danwoo/trading-lab --state open --json number -q 'length'  # 출처 열린 이슈 수
```

그리고 스크립트가 마지막에 출력하는 **번호 대조표**를 보관한다.

```
Danwoo/fintech-ai-platform#414  →  Danwoo/trading-lab #1
...
```

> ⚠ **이슈 번호는 보존되지 않는다.** GitHub 에 번호를 지정해 이슈를 만드는 API 가 없다.
> 그래서 옮긴 이슈 **본문 안의 `#N` 은 옛 레포의 번호**다 (스크립트가 본문 맨 위에 그렇게 적어 둔다).
> 자동 치환은 코드 블록·인용까지 조용히 망가뜨려서 하지 않는다 — 필요한 본문만 대조표를 보고 손으로 고친다.

ⓓ ⛔ **되돌릴 수 없다** — 만든 이슈는 닫을 수 있어도 번호는 회수되지 않는다.
다만 **두 번 돌려도 안전하다**: 옮긴 이슈 본문의 `<!-- migrated-from: … -->` 마커를 보고 건너뛴다.
잘못 옮겼으면 새 레포에서 해당 이슈를 닫고 라벨/마일스톤을 지우면 된다 (파괴적이지 않다).

**출처 이슈를 닫으려면** `--close-source` 를 명시한다 (기본 꺼짐). 개발 레포의 상태를 바꾸는 것은
별개 판단이라 이사 스크립트가 자동으로 하지 않는다.

## 5. 단계 ⑤ — 이사 후 세팅 (여기까지 해야 CI 가 돈다)

### 5.1 시크릿 — 1종

값을 이 문서에 적지 않는다. **이름만** 적는다.

| 이름 | 쓰는 워크플로 | 없으면 |
|---|---|---|
| `PROJECT_TOKEN` | `board-status.yml` · `cross-review.yml`(publish) · `merge-router.yml` | 판정 라벨이 안 붙어 리뷰 게이트 연쇄가 통째로 멎는다 |

```bash
gh secret set PROJECT_TOKEN --repo Danwoo/trading-lab      # 값은 대화형으로 입력
gh secret list --repo Danwoo/trading-lab                   # 이름만 확인 — 값은 다시 못 읽는다
```

> 이 PAT 는 **프로젝트 보드 쓰기**에 필요하다 (기본 `GITHUB_TOKEN` 으로는 Projects v2 를 못 쓴다).
> 기존 classic PAT 를 그대로 재사용한다 — 신규 발급은 필요 없다. 단 **PAT 의 레포 스코프에
> 새 레포가 포함되는지** 확인해야 한다 (fine-grained PAT 면 레포 목록에 `trading-lab` 을 추가).

### 5.2 레포 변수 — 8개 (값이 공개돼도 되는 것들)

**`ORCA_REPO_SELECTOR` 를 뺀 7개는 값을 그대로 복사한다.** 프로젝트 보드가 사용자 레벨
프로젝트(`https://github.com/users/Danwoo/projects/2`)라 **레포와 무관하게 같은 ID 가 유효하다**
(실측: `projectV2.repositories` 가 빈 목록 — 레포에 묶여 있지 않다).

```bash
R=Danwoo/trading-lab
gh variable set AUTO_MERGE            --repo $R --body 'on'
gh variable set AUTO_MERGE_METHOD     --repo $R --body 'squash'
gh variable set BOARD_PROJECT_ID      --repo $R --body 'PVT_kwHOBKkbCc4BdVSU'
gh variable set BOARD_STATUS_FIELD_ID --repo $R --body 'PVTSSF_lAHOBKkbCc4BdVSUzhX3kI0'
gh variable set BOARD_IN_PROGRESS_ID  --repo $R --body '5d54eb93'
gh variable set BOARD_IN_REVIEW_ID    --repo $R --body '13dc0393'
gh variable set BOARD_HUMAN_WAIT_ID   --repo $R --body '103dce2b'
# ORCA_REPO_SELECTOR 는 §5.6 에서 새 id 로 세운다 — 옛 값을 복사하면 옛 클론에 워크트리가 생긴다
gh variable list --repo $R            # 7개
```

> **`CROSS_REVIEW_CODEX` 는 등록하지 않는다.** `cross-review.yml` 이 참조하지만 지금 이 레포에도
> **설정돼 있지 않다** — 미설정 = off 가 의도된 상태다 (codex 한도 복귀 시 켠다).
> 워크플로가 참조하는 변수 9개 중 실제 설정된 것이 8개인 이유가 이것이다.

### 5.3 `Automatically delete head branches` — 반드시 켠다

CLAUDE.md 「브랜치 정리 규칙」이 **이 설정에 의존한다.** 꺼져 있으면 스택 PR 에서 머지된
브랜치가 살아남아, 그 위에 착륙한 커밋이 **조용히 고립**된다 (실측 사례 #261).

```bash
gh api --method PATCH repos/Danwoo/trading-lab -F delete_branch_on_merge=true
gh api repos/Danwoo/trading-lab -q '.delete_branch_on_merge'   # true
```

UI 경로: **Settings → General → Pull Requests → Automatically delete head branches**

### 5.4 브랜치 보호 — 공개되면 **처음으로 쓸 수 있게 된다**

> **이건 이관이 아니라 신규다.** 지금 이 레포에는 브랜치 보호가 **없다** — 비공개 + Free 플랜은
> 쓸 수 없기 때문이다 (실측: API 가 `Upgrade to GitHub Pro or make this repository public` 403).
> `review-gate.yml` 이 커밋 상태를 없앤 이유가 정확히 이것이었다 (required status check 가 0개라
> 그 상태는 아무것도 막지 못하면서 머지 버튼만 잠갔다).
>
> **공개 전환과 동시에 이 제약이 풀린다.** 그러면 `ci` · `frontend-ci` · `repo-scans` 의 결정론적
> 체크를 required 로 걸 수 있다 — **켤지 말지는 리드가 정한다.** 켜면 CI 가 죽어 있는 동안
> 머지가 막히므로, 지출 한도가 풀린 뒤에 켜는 편이 안전하다.

UI 경로: **Settings → Branches → Add branch ruleset** (또는 Add rule) — 대상 `main`.

### 5.5 ⚠ fork PR 워크플로 승인 — 공개 직후 **반드시** 조인다

`cross-review.yml` 머리 주석이 이것을 **배포 체크 항목으로 명시**하고 있다. 공개 레포에서
self-hosted 러너를 지키는 층이다.

```bash
gh api repos/Danwoo/trading-lab/actions/permissions/fork-pr-contributor-approval
# 공개 레포 기본값: {"approval_policy":"first_time_contributors"}

gh api --method PUT repos/Danwoo/trading-lab/actions/permissions/fork-pr-contributor-approval \
  -f approval_policy=all_external_contributors
```

UI 경로: **Settings → Actions → General → Fork pull request workflows from outside collaborators
→ `Require approval for all external contributors`**

> **기본값이 왜 부족한가.** 공개 레포의 기본은 `first_time_contributors` 다 — **두 번째 PR 부터는
> 승인 없이** 워크플로가 돈다. 자동 실행되는 것은 GitHub-hosted 잡뿐이지만(§6 참조), 이 층은
> 심층 방어의 바깥 껍질이라 조여 두는 편이 맞다.

### 5.6 self-hosted 러너 재등록 + Orca 레포 등록

러너 등록 토큰은 **레포에 묶인다.** 새 레포에서 새 토큰을 받아 다시 등록해야 한다.
기존 두 대(`wsl-harness-runner`·`wsl-harness-runner-2`)를 옮긴다.

UI 경로: **Settings → Actions → Runners → New self-hosted runner** (Linux x64) — 화면이 주는
`./config.sh --url … --token …` 을 러너 머신에서 실행한다.

- **라벨을 `harness-review` 로 준다** — `cross-review.yml` 의 `runs-on: [self-hosted, harness-review]`
  가 이 이름으로 고른다. 빠지면 리뷰 잡이 영원히 `queued` 로 대기한다.
- 러너 서비스 사용자는 **claude·kimi CLI 인증을 가진 계정**이어야 하고 `git`·`jq` 가 있어야 한다.
- 옛 레포의 러너는 이사가 끝난 뒤 제거한다 (보관용 레포에 러너를 남길 이유가 없다).

```bash
gh api repos/Danwoo/trading-lab/actions/runners -q '.runners[] | "\(.name) \(.status) \([.labels[].name]|join(","))"'
# → 두 줄, 각각 online, 라벨에 self-hosted·harness-review 포함
```

Orca 경로(§ `cross-review.yml` 실행 경로 이중화)를 쓰려면 **새 로컬 클론을 Orca 에 등록**한다.

```bash
git clone https://github.com/Danwoo/trading-lab.git ~/projects/trading-lab
orca repo add ~/projects/trading-lab
orca repo list --json | python3 -c "import json,sys;[print(r['id'], r['path']) for r in json.load(sys.stdin)['result']['repos']]"
gh variable set ORCA_REPO_SELECTOR --repo Danwoo/trading-lab --body 'id:<위에서 나온 새 id>'
```

> **옛 셀렉터(`id:fd01c1bc-…`)를 복사하지 마라.** 그것은 `~/projects/fintech-ai-platform`
> (보관용 클론)을 가리킨다 — 새 레포의 리뷰 워크트리가 **옛 클론에** 생긴다.
> Orca 경로를 아예 끄려면 이 변수를 등록하지 않으면 된다 (헤드리스 폴백으로 수렴한다).

### 5.7 레포 첫인상 — 공개본은 README 가 얼굴이다

- **Settings → General**: Description · Website · Topics 를 채운다 (지금은 셋 다 비어 있다).
- **Settings → General → Features**: Issues 켬 · Wiki 끔 · Discussions 은 판단.

## 6. 단계 ⑥ — CI 첫 초록 확인

이사는 「push 가 끝난 때」가 아니라 「새 레포에서 CI 가 초록인 때」 끝난다.

ⓐ 명령 — 아무 브랜치나 하나 올려 PR 을 만든다.

```bash
cd ~/projects/trading-lab
git switch -c chore-move-smoke && git commit --allow-empty -m "chore: 이사 후 CI 첫 기동 확인" && git push -u origin HEAD
gh pr create --fill
gh pr checks --watch
```

ⓑ 기대 — `ci` · `frontend-ci` · `repo-scans` 가 돈다. `cross-review` 는 self-hosted 러너가
붙어 있어야 돈다.

ⓒ 확인 — 워크플로별로 「돌았는가」와 「왜 안 돌았는가」를 구분한다.

```bash
gh run list --repo Danwoo/trading-lab --limit 20
```

| 증상 | 원인 | 고치는 자리 |
|---|---|---|
| 리뷰 잡이 `queued` 에서 안 움직인다 | 러너 미등록 또는 라벨 불일치 | §5.6 |
| 판정 라벨이 안 붙는다 | `PROJECT_TOKEN` 미등록 / PAT 스코프에 새 레포 없음 | §5.1 |
| 보드에 카드가 안 생긴다 | `BOARD_*` 변수 미등록 | §5.2 |
| 리뷰 워크트리가 옛 클론에 생긴다 | `ORCA_REPO_SELECTOR` 가 옛 id | §5.6 |
| 라벨을 붙이는 단계가 실패한다 | 라벨 이관 누락 | §4.3 |

ⓓ 되돌리기 — 이 단계는 전부 되돌릴 수 있다. 스모크 PR 은 닫고 브랜치를 지운다.

> ⚠ **Actions 를 아예 끄는 선택지도 있다** (Settings → Actions → General → Disable actions).
> 하네스 자동화 워크플로 8종은 공개 레포에서 시크릿·러너가 붙기 전까지 실패하거나 무동작한다 —
> 리드 결정은 「워크플로를 전부 넣는다」였고, **Actions 를 켤지는 공개 시점에 사람이 정한다**(#360).

## 7. 공개되면 달라지는 위험

### 7.1 self-hosted 러너 + 공개 레포 — 가드는 **충분하다**

남이 보낸 PR 의 코드가 리드 컴퓨터에서 도는 경로가 열리는가를 코드로 확인했다. **닫혀 있다.**

- self-hosted 를 쓰는 잡은 **`cross-review.yml` 의 `review` 하나뿐**이다
  (`grep -rn "runs-on" .github/workflows/` — 나머지는 전부 `ubuntu-latest`).
- 그 잡에 가드가 **2중**으로 걸려 있다.
  - `route` 잡: `if: … head.repo.full_name == github.repository` → fork PR 이면 **스킵**
  - `review` 잡: `needs: route` (선행이 스킵되면 함께 스킵) **＋ 같은 same-repo 조건을 자기도 검사**
  - `review` 에는 `always()` 가 없다 — 그래서 `needs` 스킵이 실제로 전파된다.
- `pull_request_target` 사용 **0건**이다 (fork 의 코드를 신뢰 컨텍스트에서 도는 전형적 사고 경로).

**잔여 표면 두 가지는 위험이 아니라 알고 있어야 할 사실이다.**

1. **`publish` 잡은 `if: always()` 라 fork PR 에서도 돈다.** 다만 `ubuntu-latest` 이고,
   fork PR 의 `GITHUB_TOKEN` 은 GitHub 이 **읽기 전용으로 내려주며**(`permissions:` 블록으로
   올릴 수 없다) `secrets.PROJECT_TOKEN` 도 비어 있다. 즉 **아무것도 못 쓴다** — 대신
   **모든 fork PR 에 빨간 X 가 하나 붙는다.** 보안 문제가 아니라 첫인상 문제다.
2. **same-repo PR 은 이 워크플로 파일 자체를 고쳐 실행시킬 수 있다.** 공개 레포에서도 이건
   **push 권한이 있는 사람**에 한정된다. `cross-review.yml` 이 「잔존 표면」으로 이미 문서화하고
   수용한 자리다 (에이전트 비적대 위협 모델).

### 7.2 공개되면 읽히는 것 — 게이트와 **겹치지 않는 축**으로 훑었다

`verify_public_release_tree.py` 가 보는 축(제거 대상 blob·시크릿 패턴·미등록 자산)이 아니라,
**「비공개라서 넘어갔던 운영 정보」** 축으로 전수 조사했다. 재현 명령을 함께 적는다.

| 축 | 결과 | 재현 |
|---|---|---|
| 로컬 절대경로 `/home/<계정>/` | 1파일 — 전부 문서의 **가상 계정** (`deploy-user`·`acme`) | `git grep -lI -E '/home/[a-z0-9_-]+/'` |
| 실제 계정명 `tjeksdn1` | **1건 — `cross-review.yml:64` 의 관측 출력** (아래 발견) | `git grep -nI 'tjeksdn1'` |
| 사설 IP | 4파일 — 전부 문서 예시·마스킹 테스트 픽스처 | `git grep -lIE '\b(192\.168\.\|10\.\|172\.(1[6-9]\|2[0-9]\|3[01])\.)'` |
| 이메일 주소 | 전부 `example.com`·`x.co` 등 예약·가상 도메인 | `git grep -hoIE '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}' \| sort -u` |
| 외부 호스트 전수 | 공개 벤더·문서 도메인, `.test`/`.invalid` 예약 TLD, compose 서비스명, **RFC 5737 문서용 IP**(`192.0.2.x`·`198.51.100.x`) | `git grep -hoIE 'https?://[A-Za-z0-9._-]+' \| sed -E 's\|https?://\|\|' \| sort -u` |
| `.env.example` 의 실제 값 (게이트가 **못 보는** 자리로 문서화된 곳) | 12파일 전수 — 시크릿 모양 키의 값이 **전부 `CHANGE_ME`/`EMPTY`** | 아래 |
| 레포 이름 하드코딩 | 6파일 (`fintech-ai-platform`) — 문서 링크·스크립트 주석의 실측 기록 | `git grep -lI 'fintech-ai-platform'` |

```bash
# .env.example 의 시크릿 모양 값 전수 — 게이트가 명시적으로 "못 막는다"고 적어 둔 자리다
for f in $(git ls-files | grep -iE '\.env'); do
  grep -nE '^[A-Za-z_]*(KEY|SECRET|TOKEN|PASSWORD|PASS|CRED|DSN|URI|URL)[A-Za-z_]*=.+' "$f" | sed "s|^|$f:|"
done
```

**판정: 이 축에서 이사를 막는 것은 없다.** 발견 2건은 아래에 적고, 둘 다 비차단이다.

- **`cross-review.yml:64` 에 리드의 로컬 계정명이 그대로 있다** (`tjeksdn1@localhost: ~/orca/…`).
  터미널 제목을 그대로 옮겨 적은 실측 기록이라 의도된 것이지만, 공개되면 리드의 로컬 사용자명이
  공개된다. 위험도는 낮다(계정명 하나로 되는 것이 없다).
- **`frontend/prisma/init/seed.sql` 의 데모 계정 비밀번호가 공개된다** — `admin@example.com` /
  `operator@example.com` 둘 다 `changeme1234` (주석에 그대로 적혀 있다). 로컬 스타터의 시드라
  의도된 것이고 이름부터 `changeme` 지만, **이 시드를 그대로 둔 채 외부에 노출되는 인스턴스를
  띄우면 관리자 계정이 공개 크리덴셜이 된다.** 공개 전에는 사실이 아니었다 — 공개가 바꾸는 것이 이것이다.

## 8. 이 런북이 못 하는 것

- **공개된 것의 회수.** §4.2 부터는 되돌아갈 수 없다. 그래서 §3 드라이런이 먼저다.
- **이슈 번호 보존.** GitHub API 에 그런 것이 없다. 대조표가 대신한다 (§4.3).
- **PR·이슈 코멘트·이력 이관.** 구조적으로 못 옮긴다 — 보관용 레포가 그 역할을 한다.
- **러너 재등록 자동화.** 등록 토큰이 레포에 묶이고 대화형이라 사람이 친다 (§5.6).
- **CI 가 실제로 초록인지의 사전 확인.** 새 레포에서 처음 돌 때까지는 알 수 없다 (§6).
