봇을 만들어 굴리는 흐름 — 목데이터로 채운 실제 화면

전략(파일) → 봇(조합) → 백테스트 → 리더보드 → 자연어 생성 순서입니다. 숫자는 전부 그럴듯한 목데이터이고, 화면 구조와 조작 흐름을 판단하시라고 채웠습니다.

1 봇 만들기 — 전략을 고르면 폼이 스스로 자란다

전략 파일이 "이 값을 이 범위에서 조절 가능"을 선언하므로, 왼쪽에서 전략을 담으면 가운데 폼이 그만큼 늘어납니다. 새 전략을 추가해도 이 화면은 안 고칩니다.

2 백테스트 리포트 — 가정을 숨기지 않는다

체결가격·수수료·슬리피지·기간·유니버스가 결과를 좌우합니다. 접어두지 않고 결과 바로 옆에 상설로 둡니다 — 이 값을 모르고 보는 수익률은 숫자가 아니라 광고입니다.

3 리더보드 — 내 실계좌를 같은 표에 넣는다

봇끼리만 비교하면 "그래서 내가 직접 하는 것보다 나은가"에 답을 못 합니다. 실계좌를 같은 기준으로 한 행에 넣습니다.

UX 결정 실계좌 행은 정렬해도 자리를 지키지 않고 같이 섞입니다. 위에 고정하면 기준점이 아니라 주인공이 되고, "내가 3등"이라는 사실이 흐려집니다.

4 말로 전략 만들기 — 결과물이 파일이라 되짚을 수 있다

LLM 은 연구 시점에만 코드를 만들고, 장중엔 그 코드가 결정론적으로 돕니다. 만들어진 것이 파일이라 git 에 남고 diff 로 비교됩니다.

전략 만들기 · 자연어 프롬프트 고쳐 재생성전략 커밋
대형주에서 20일선 눌림목 잡는 전략 만들어줘. 근데 시장 전체가 하락장이면 쉬게 해줘.
두 부분으로 나눴습니다.
① 눌림목 — 20일선 위에 있던 종목이 20일선까지 조정 후 반등하는 첫 봉
② 하락장 회피 — KOSPI 가 자기 60일선 아래면 전 종목 관망

"대형주"는 유니버스 조건이라 전략 파일이 아니라 봇 설정에 넣었습니다 — 같은 전략을 중소형주에도 쓸 수 있게요.
즉시 백테스트 (기본 가정) 연환산 +14.2% · MDD -16.9% · 샤프 1.21
거래 88회 · 승률 52.3% · 평균 보유 9.1일
생성된 파일 · strategies/pullback_ma20.py +34
+ params = { + "ma_period": Range(10, 60, default=20), + "bounce_pct": Range(0.5, 5.0, default=1.5), + "market_ma": Range(20, 120, default=60), + } + timeframe = "1d" + def entry(bar, ind, market): + if market.close < market.ma(p.market_ma): + return False # 하락장 — 전 종목 관망 + touched = bar.low <= ind.ma(p.ma_period) + bounced = bar.close > ind.ma(p.ma_period) * (1 + p.bounce_pct/100) + return touched and bounced
파라미터 3개가 선언됐으므로, 커밋하는 순간 1단계 봇 만들기 화면에 슬라이더 3개가 자동으로 생깁니다.
UX 결정 커밋 전에 백테스트 결과를 먼저 보여줍니다. 코드를 읽을 줄 몰라도 판단할 수 있어야 하고, 코드를 읽을 줄 알면 오른쪽 diff 로 검산합니다. 두 종류의 사용자가 같은 화면에서 각자 판단합니다.

이 흐름에서 제가 판단을 요청드리는 것

① 「모의 운용 시작」이 백테스트 리포트 안에 있는 게 맞습니까? 백테스트를 본 직후가 그 결정을 내리는 순간이라 여기 뒀습니다. 별도 화면으로 빼면 흐름이 끊깁니다.

② 봇 만들기에 「저장」을 없앤 것 — 초안 자동저장 + 「백테스트 실행」 하나만 뒀습니다. 검증 안 된 봇을 저장하는 것에 의미가 없다고 봤는데, 만들다 말고 나가는 경우를 생각하면 명시적 저장이 안심될 수도 있습니다.

③ 리더보드에 실계좌를 섞은 것 — 고정하지 않고 같이 정렬됩니다. "내가 3등"이 그대로 보이는 게 이 제품의 요점이라 봤습니다.

다음으로 아침 브리핑(터미널 첫 상태) · 승인 대기 · 모의 운용 중인 봇의 실시간 화면을 이어서 그리겠습니다. 그게 매일 아침 실제로 보게 되는 화면이라 가장 중요합니다.
