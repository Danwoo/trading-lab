앱 셸 구조 — 사이드바가 애매한 진짜 이유

터미널을 볼 때 화면에 사이드바가 두 개, 크롬이 두 겹입니다. 색·간격으로는 절대 안 풀립니다. 이건 CSS 가 아니라 라우팅·레이아웃 구조 문제입니다.

①②메뉴 사이드바 + 종목 사이드바가 동시에 세로줄 두 개를 만듭니다. 그 사이에 탭 바와 iframe 경계까지 들어가 실제 작업 영역이 네 겹 안쪽입니다.
현행 — 진단용 S1. 그대로 둔다 구조 변경 0. 색만 P2 로 갈아입힙니다. "애매하다"는 감각은 그대로 남습니다 — 원인을 안 건드리기 때문입니다. 결정 로그의 터미널은 탭 밖 도 계속 미실행 상태로 남습니다.

추천 S2. 아이콘 레일 + 컨텍스트 사이드바 제품 전역 이동(터미널·포트폴리오·리서치·관리)은 얇은 아이콘 레일이 맡고, 넓은 사이드바는 지금 화면의 맥락(종목 목록) 하나만 맡습니다. 상단바에 현재 종목·장 상태가 올라와 "지금 무엇을 보고 있는가"가 한 줄로 읽힙니다. 기존 MDI 탭은 /admin 관리 화면에만 남깁니다 — 버리지 않습니다.

최소 S3. 터미널 전체화면 + 런처 크롬을 최대한 지웁니다. 화면 대비 데이터 면적이 가장 넓고 성격이 가장 강합니다. 대신 다른 화면이 있다는 사실 자체가 안 보입니다 — 처음 클론한 사람이 관리·포트폴리오 화면을 못 찾을 위험이 실제로 있고, 이건 G1(남이 받아서 띄운다)과 정면으로 부딪힙니다.

정직하게 붙이는 비용

S2·S3 은 CSS 작업이 아닙니다. app/(main)/layout.tsx 가 메인 프레임에서 children 을 렌더하지 않는 구조를 바꿔야 하고, GlobalTabs 의 iframe 경로에서 터미널을 빼내야 합니다. 디자인 개선과 별개의 구조 변경이고, 회귀 위험도 여기가 가장 큽니다 (탭 상태 저장 tabStore, 권한 게이트, isEmbed 분기가 전부 이 구조에 물려 있습니다).

그래서 순서를 나누는 것도 선택지입니다 — 먼저 토큰·컴포넌트만 P2 로 정리(S1 상태에서) 하고, 셸 개편은 별도 작업으로 뒤에 두는 것. 화면은 확실히 나아지지만 "사이드바가 애매하다"는 그때까지 남습니다. 동시에 갈지, 나눠 갈지도 알려주십시오.
