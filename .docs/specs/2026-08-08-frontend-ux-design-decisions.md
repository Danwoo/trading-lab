## 0. 결론

**시각 시스템은 확정됐고, 제품 UX 는 화면을 그려 제안했으나 제품 의도가 뒤늦게 드러나 홈 구조를 다시 잡아야 한다.** 코드는 아직 한 줄도 바꾸지 않았다.

| | 상태 |
|---|---|
| 색·타이포·선·상태 토큰 | **확정** — [디자인 시스템](../4-아키텍처/디자인-시스템.md) |
| 봇 흐름 · 일상 흐름 · 화면 지도 | 화면으로 제안됨 — **결정 대기 16건** |
| 홈 구조 | **재설계 필요** (§0.1) |
| 구현 | 미착수 |

### 0.1 제품 의도 — 뒤늦게 드러난 것

리드의 말로 정리하면 이렇다.

> **"퀀트 트레이딩을 하는 투자 전문가처럼, 전 종목을 계속 둘러보고 종목을 골라 매매한다. 재무와 기술적 지표를 둘 다 섞는다. 결국 AI 시대의 투자 방법을 실험하고, 내 의도를 넣어서 해보겠다는 것."**

**이 제품은 트레이딩 터미널이 아니라 투자 가설 실험 플랫폼이다.**

```mermaid
flowchart LR
  H["가설을 넣는다<br/>(의도 · 자연어)"] --> U["전 종목에 건다<br/>(재무 + 기술 팩터)"]
  U --> V["검증한다<br/>(백테스트 · holdout)"]
  V --> C["비교한다<br/>(리더보드 · 실계좌)"]
  C --> H
```

**설계에 미치는 영향 — 앞서 그린 화면의 전제가 바뀐다.**

| 이전 전제 | 정정 |
|---|---|
| 홈은 터미널(한 종목 문맥) | **홈은 실험대.** 터미널은 "왜 이 종목이 뽑혔나"를 확인하러 들르는 곳 |
| 사이드바 관심종목이 출발점 | **출발점은 전 종목 유니버스.** 관심종목은 곁가지 |
| 스크리너는 "터미널 밖 화면" 한 줄 | **스크리너·팩터 편집이 제품의 심장.** 아직 설계가 없다 |
| 랭킹은 월 1회 리밸런싱 | **매일 갱신 + 수동 언제든.** 국내 공식 오픈API 가 날짜별 전종목 스냅샷이라 전 종목 일봉 스캔은 오히려 싸다 |
| AI 전략 생성은 부가 기능 | **실험의 입력 장치이자 제품의 중심.** 다중검정·과적합 방어가 곁가지가 아니라 신뢰성 그 자체 |

**"계속 둘러보기"의 실현 가능 범위** — 소스 구조가 2단을 강제한다.

| 단 | 범위 | 주기 | 가능한가 |
|---|---|---|---|
| 1단 | 전 종목 약 2,800개 · 일봉 + 재무 | 매일 장마감 후 자동 + 수동 언제든 | **가능** — 날짜별 전종목 스냅샷이라 종목 수가 비용이 아니다 |
| 2단 | 후보 100~200개 · 분봉·실시간 | 장중 계속 | **미확정** — 국내는 증권사 계좌 필요, 동시 구독 상한이 조사 미완. 미국 Alpaca 는 분당 200회·종목당 호출이라 전 종목 불가 |

## 1. 확정된 것

| 항목 | 확정 | 기각한 것과 이유 |
|---|---|---|
| 바탕 | **잉크 바탕 · 종이 글자** — 배경은 차갑고(`#0D0F11`) 글자는 따뜻하다(`#E6E4E0`) | 따뜻한 크림 바탕 기각 — 현재 AI 도구들의 공용 팔레트라 "AI 같다"로 읽힌다 |
| 라이트 | 같은 원리를 명도만 뒤집는다 — 바탕 `#E8EAEC`, 글자 `#2E2B26` | 따뜻함이 글자에만 있어 크림으로 흐를 여지가 구조적으로 없다 |
| 등락색 | 상승 `#DB4F3E` / 하락 `#4A8CC8` (중채도) | 저채도 기각 — 밀집 표에서 판별이 느리다. 고채도 기각 — 차분한 바탕과 성격이 부딪히고 눈이 빨리 피로하다. Tailwind 기본값은 전부 배제 |
| 액센트 | **두지 않는다.** 강조는 선 굵기·글자 굵기·잉크 명도 | 적·청·녹은 등락색이 점유, 분홍·보라는 배제. 남은 황·청록 계열은 중간 채도에서 값싸 보인다. 액센트 면적은 화면의 2% 남짓이라 시스템을 흔들 값이 아니다 |
| 타이포 | 크기를 12–13px 좁은 대역에 묶고 **굵기 3단 + 명도 4단**으로 위계 | 크기 대비 기각 — 패널이 여럿인 터미널에서 제목이 반복돼 소란스럽다. 대문자 라벨 조판 기각 — 한글에 대문자가 없어 효과가 절반 |
| 셸 | **아이콘 레일 + 컨텍스트 사이드바** | 현행(사이드바 2개 + iframe) 기각 — "사이드바가 애매하다"의 원인. 전체화면+런처 기각 — 다른 화면을 못 찾아 G1 과 충돌 |
| 순서 | **① 토큰·컴포넌트 → ② 셸 개편** | 동시 진행 기각 — 셸은 `tabStore`·권한 게이트·`isEmbed` 가 물린 최고 위험 구간 |

## 2. 결정이 필요한 것

각 항목은 **제 의견을 먼저 적고, 반대 근거를 함께** 적는다. 안 정하고 넘어가면 구현 중에 임의로 정해지고, 그때 되돌리는 비용이 지금보다 크다.

### D1. 데이터 테이블 행 높이

관리 화면 12개가 전부 표다. 타이포(굵기·명도 위계)를 고르면서 터미널은 **26px** 로 정해졌으나, 관리 화면까지 같이 갈지는 안 정했다.

- **㉮ 전부 26px** — 한 화면 22행. 밀도 최고
- **㉯ 전부 34px** — 한 화면 17행. 클릭 표적 넉넉
- **㉰ 표는 26 / 폼은 34** ← **제 의견**

> 터미널은 매일 오래 보고 관리 화면은 가끔 연다. 사용 방식이 실제로 다르니 나누는 것이 정당하다. 다만 **규칙이 하나 늘어난다.**

### D2. 봇 만들기에 「저장」 버튼을 두지 않는 것

초안은 자동 저장되고, 사용자가 누르는 것은 「백테스트 실행」 하나다.

- **㉮ 저장 없음** ← **제 의견** — 검증 안 된 봇을 저장하는 것에 뜻이 없고, 두 버튼은 매번 "뭘 눌러야 하지"를 묻게 만든다
- **㉯ 명시적 저장 추가** — 만들다 말고 나가는 경우 안심된다

> 반대 근거가 약하지 않다. 자동 저장을 **사용자가 믿지 못하면** 저장 버튼이 없는 화면은 불안하다. 상단의 "초안 저장됨 14:38" 표시로 충분한지는 실제로 써 봐야 안다.

### D3. 「모의 운용 시작」을 백테스트 리포트 안에 두는 것

- **㉮ 리포트 안** ← **제 의견** — 백테스트를 본 직후가 그 결정을 내리는 순간이다
- **㉯ 별도 화면** — 승격 결정을 무겁게 만든다

### D4. 리더보드에 실계좌를 섞는 것

봇들과 같은 표, 같은 정렬 대상. 상단 고정하지 않는다.

- **㉮ 섞는다** ← **제 의견** — "내가 3등"이 그대로 보이는 것이 이 제품의 요점이다. 고정하면 기준점이 아니라 주인공이 된다
- **㉯ 상단 고정** — 항상 기준이 눈에 있다

### D5. 모의 주문 「일괄 승인」을 허용할 것인가 ⚠

**가장 되돌리기 어려운 결정이다.** 지금은 모의 체결이라 실제 돈이 안 움직인다. 그러나 **일괄 승인에 익숙해진 손은 실주문 승격 후에도 그대로 누른다.**

- **㉮ 지금은 일괄 허용, 실주문 단계에서 막는다** — 편하지만 그때 습관을 되돌려야 한다
- **㉯ 처음부터 하나씩만 승인** ← **제 의견** — 승인 행위 자체를 훈련시킨다
- **㉰ 일괄 허용하되 실주문은 아예 다른 조작으로 분리** (버튼 위치·색·확인 절차를 다르게)

> 이 제품의 결정 로그가 이미 *"실주문은 백테스트·검증이 끝난 뒤 승격한다"* 로 못박혀 있다. 승인 UX 도 같은 신중함을 지금부터 갖는 편이 일관된다.

### D6. 첫 실행에서 키 등록을 강제하지 않는 것

API 키 0개로 기동되고, 전 패널이 임시 데이터 배지를 단 채 둘러볼 수 있다.

- **㉮ 강제하지 않음** ← **제 의견** — G1 판정은 "자기 화면을 띄운다"이지 "키를 넣는다"가 아니다. 모달로 막으면 "일단 뭔지 보자"는 사람이 그 자리에서 이탈한다
- **㉯ 키 등록 전에는 진입 차단** — 가짜 숫자를 아예 안 보여준다

> ㉯의 근거도 진짜다 — 임시 데이터를 실데이터로 오인할 위험이 0이 된다. 다만 그 위험은 **배지와 해칭**으로 이미 막고 있다.

### D7. 관리자 화면만 MDI 탭을 남기는 것

터미널·봇·리서치·포트폴리오·설정은 탭 없이 레일로 이동하고, 관리자만 기존 탭 구조를 유지한다.

- **㉮ 관리자만 탭 유지** ← **제 의견** — 코드·메뉴·권한을 여러 개 열어 놓고 오가는 작업이라 탭이 실제로 맞고, **이미 동작하는 것을 굳이 바꾸지 않는다**
- **㉯ 탭을 전부 제거** — 구조가 하나로 단순해지지만 관리 작업이 불편해지고 변경 범위가 커진다

### D8. 화면 사이 문맥 전파 규칙

| 이동 | 제안 |
|---|---|
| 터미널 → 봇 | 종목이 **따라간다** (해제 가능한 칩) |
| 터미널 → 리서치 | 종목이 **따라간다** |
| 터미널 → 포트폴리오 | **안 따라간다** — 전체 관점이 목적인 화면이라 한 종목으로 좁히면 존재 이유가 사라진다. 대신 그 행을 하이라이트 |
| 봇 → 터미널 | **봇이 따라간다** — 「봇 판단」 패널이 그 봇을 편 상태로 열린다 |

> 포트폴리오만 예외인 것이 일관성을 깬다는 반론이 가능하다. **"문맥은 항상 따라간다"로 단순화**할지 판단이 필요하다.

### D9. 라이트 모드를 실제로 출시할 것인가

두 모드 다 채택하기로 했다. 비용을 다시 확인한다 — **`.tsx` 158개가 두 모드에서 각각 검증돼야 한다.**

- **㉮ 둘 다 출시** (현재 결정)
- **㉯ 다크 단일 출시 + 토큰 이름만 모드 중립** ← **원래 제 의견이었고 지금도 유지한다**

> "있으면 좋다"로 넣으면 **절반은 라이트에서 깨진 채 방치**된다. 다만 시안에서 라이트가 쓸 만하다고 판단하셨으므로, 이 항목은 **재확인**만 요청한다. 유지하시면 그대로 간다.

### D10. 구현 착수 순서

- **㉮ 토큰 → 공용 컴포넌트 → 터미널 → 관리 화면 → 셸 개편** ← **제 의견**
- **㉯ 토큰 → 터미널 전체 완성 → 나머지**
- **㉰ 토큰 → 셸 개편 먼저**

> ㉮를 권하는 이유 — 공용 컴포넌트(버튼·필드·표·배지)를 먼저 고치면 **158개 파일이 동시에 올라간다.** 화면 단위로 가면 같은 컴포넌트를 여러 번 만진다. ㉰는 최고 위험 구간을 먼저 여는 것이라 권하지 않는다.

### D11. 유니버스를 시점(as-of)으로 재구성할 것인가 — ✅ **결정됨: 재구성한다**

리드 결정: *"과거까지도 다 진행해야죠. 백테스트도 그렇고 실험하는 데 있어서 과거 데이터로 실험하는 게 중요하잖아요."*

**그리고 재조사 결과 비용이 걱정보다 훨씬 작다** ([파이프라인 §4.6.1](../4-아키텍처/시세-데이터-파이프라인.md)).

| 걱정했던 것 | 실제 |
|---|---|
| DB 에 다 넣기 어렵다 | 일봉 전 종목 10년 ≈ **1.5GB** |
| 적재가 오래 걸린다 | `basDt` 날짜별 전종목 호출이면 **2,450회 → 하루** (한도 10,000회/일) |
| 스냅샷 테이블을 따로 만들어야 한다 | **불필요.** 날짜별로 적재하면 그날 응답에 있던 종목이 곧 그날의 유니버스다 |
| 호가까지 다 연결해야 한다 | **불필요.** 백테스트는 일봉 OHLCV + 슬리피지 가정으로 한다 |

> **남은 작업은 어댑터에 날짜별 경로를 추가하는 것 하나다.** 현재 `fetch_daily` 는 `likeSrtnCd`(종목 하나씩)만 쓴다.
> 이 경로 하나가 **생존편향·미래참조·사후선택편향 셋을 동시에 해소**한다.
>
> **전제 검증이 남아 있다** — `basDt` 단독 조회가 정말 전 종목을 주는지, 그 응답에 **당시 상장돼 있던(이후 폐지된) 종목이 포함되는지.** 키 발급 후 첫 작업으로 확인한다. 포함되지 않으면 이 결정의 근거가 무너지므로 그때 다시 판단한다.

### D12. 수정주가 확보 전에 백테스트 리포트를 노출할 것인가 ⚠

**재조사로 사실관계가 하나 바뀌었다** — `ADJ_POLICY = "raw"` 는 구현 미비가 아니라 **소스가 원주가만 주기 때문**이다. 공공데이터포털 시세에는 수정주가가 아예 없다.

그래서 이 결정은 "구현할까 말까"가 아니라 **"자본변동 데이터를 어디서 받아 직접 계산할까"** 로 바뀐다. 그리고 소스 선택에 라이선스 함정이 있다 — 금융위원회_주식권리일정정보는 **공공누리 제2유형(상업적 이용금지)** 이라 호스팅 모드로 가면 깨지고, **OpenDART** 를 써야 한다 ([파이프라인 §4.6.2](../4-아키텍처/시세-데이터-파이프라인.md)).

어댑터는 둘 다 `ADJ_POLICY = "raw"` 이고 수정계수 테이블(`tn_corporate_action`)은 **문서에만 있고 마이그레이션에 없다.**

- **㉮ 확보 후 노출** ← **제 의견** — 무수정 원본에 이평·손절을 걸면 액면분할 종목에 **-50% 가짜 갭**이 생겨 신호가 통째로 오염된다. 배당도 수익에서 빠져 배당 전략은 구조적으로 저평가된다
- **㉯ 지금 노출 + 「가격수익 기준」 라벨 상설**

> 어느 쪽이든 화면은 **`BarsOut.adj_policy` 원값을 그대로 표시**해야 한다. 구간에 정책이 섞이면 `"raw,adj_split"` 처럼 쉼표로 이어 오는데, 이걸 "적용/미적용" 이분법으로 접으면 혼재 사실이 사라진다.

### D13. 실주문 승격을 무엇으로 판정할 것인가 — IS 인가 OOS 인가 ⚠

- **㉮ 아웃오브샘플(holdout) 통과 필수** ← **제 의견** — 리포트가 학습구간/검증구간 두 벌이 되고, 「모의 운용 시작」은 OOS 통과 전 비활성. 리더보드 기본 정렬도 OOS 열로
- **㉯ 백테스트(IS) 성과로 판정** — 지금 시안이 이렇다

> 실험 플랫폼은 **같은 데이터로 여러 번 시도**하는 것이 정상 동작이다. 그래서 다중검정이 구조적으로 일어난다. 시도 횟수를 기록하지 않으면 리더보드 1등은 실력이 아니라 **N번 중 최댓값**이다.

### D14. 지표에 불확실성을 표시할 것인가

880 세션 기준 **샤프의 표준오차가 약 0.54** 다. 시안 리더보드 5행의 95% 신뢰구간이 **서로 전부 겹친다** — 현재 순위는 통계적으로 구분되지 않는다.

- **㉮ `1.14 ±0.54` 로 표기하고 구간 겹치는 행은 동순위로 묶는다** ← **제 의견**
- **㉯ 단일 값만 표시** — 깔끔하지만 없는 정밀도를 주장한다

### D15. 모의 단계에서 사람 승인이 필요한가

**제가 전제로 깔고 물었던 것(D5)의 앞 단계다.** 모의 체결은 되돌릴 수 있으므로 결정 로그의 *"자동은 되돌릴 수 있는 것만"* 규칙대로면 **자동이어야 한다.**

- **㉮ 모의는 자동, 실주문만 승인** ← **제 의견**
- **㉯ 모의도 승인** (지금 시안)

> ㉯의 부작용이 크다 — 밤사이 신호를 아침에 승인하면 **승인 지연이 곧 체결가 괴리**가 되어, 리더보드의 「봇 vs 실계좌」가 봇의 성과가 아니라 **내 승인 습관의 성과**를 재게 된다. 백테스트 가정(다음 봉 시가)과도 어긋나 재현성이 깨진다.

### D16. 임시 데이터 신호에 색을 한 개 허용할 것인가

액센트를 없앤 결정과 FR-020(눈에 띄는 임시 데이터 배지)이 정면으로 부딪힌다. 현행 해칭·배지가 전부 `--signal-warn`(앰버) 하나에 얹혀 있다.

- **㉮ 무채 + 해칭 + 반전 블록만으로 간다** ← **제 의견** (시안에서 그렇게 그렸다)
- **㉯ `--provenance-placeholder` 를 다섯째 데이터색으로 편입** — 액센트가 아니라 **데이터 정직성 토큰**으로

> ㉮가 실제로 충분한지는 **placeholder 패널 스크린샷 한 장을 승인하는 것**으로 판정하는 게 가장 싸다. 여기는 "위계"가 아니라 "믿지 말라는 경고"라서 이질감이 필요한 자리다.

## 3. 작업 중 발견한 것

**이번 작업 범위 밖이다.** 고치자는 제안이 아니라 기록이다.

| # | 발견 | 근거 | 왜 문제인가 |
|---|---|---|---|
| F1 | **MCP 6개 중 2개만 응답에 `source` 를 싣는다** | `disclosure`·`doc-search` 만 있음. `market-data`·`news`·`portfolio`·`web` 없음 | FR-019(각 패널은 출처를 표시)와 G2(모든 숫자가 출처를 갖는다)에 정면으로 걸린다. 시세·뉴스 패널은 **표시하고 싶어도 받을 값이 없다** |
| F2 | **Pretendard 9벌(17MB, 18파일) 중 4벌은 사용 0곳** | `font-*` 사용 집계에 Thin·ExtraLight·Light·Black 없음 | 초기 로드 낭비. 400/500/700 3벌 + woff2 만 남기면 3파일 |
| F3 | **빈·오류 문구가 22개 파일에 5가지로 흩어져 있다** | `없습니다`(15) · `오류가 발생`(8) · `데이터가 없`(5) · `항목이 없`(2) · `불러오지 못`(2) | 같은 뜻을 다섯 가지로 말한다. "오류가 발생했습니다"만 있으면 사용자가 할 수 있는 것이 없다 |
| F4 | **focus 처리가 혼용돼 있다** | `focus:` / `focus-visible:` 혼용 + `ring-blue-500/40` 하드코딩 | 대체 링이 없는 파일은 0건이라 **명백한 접근성 구멍은 없다.** 통일 대상일 뿐 |
| F5 | **터미널이 iframe 탭 안에서 돈다 — 결정 로그와 코드가 어긋나 있다** | `app/(main)/layout.tsx` 가 메인 프레임에서 `children` 을 렌더하지 않고, `GlobalTabs` 가 `<iframe src={tab.path}>` 로만 렌더 | 결정 로그 2026-07-29 *"터미널이 메인 화면 — 기존 MDI 탭 밖"* 이 미실행 상태. 문맥 브로드캐스트가 iframe 경계를 못 넘는다 |
| F6 | **구 토큰이 18개 파일 72곳에 살아 있고, `--ink-muted` 는 이름이 같고 값만 다르다** | `slate-void/panel/line`·`ink-primary`·`signal-warn` grep 실측. 구 `--ink-muted` `107 118 134` → 신 `139 135 127` | 구 소비자가 **컴파일·린트를 통과하면서 값만 갈아탄다.** §8 의 CI 그물은 Tailwind 기본 팔레트와 hex 만 잡아 이 stale 토큰을 영원히 못 잡는다. **구 토큰 이름을 재사용하지 말고 전부 신설**해야 기계가 이주 완료를 판정할 수 있다 |
| F7 | **`applyMarketColorPreset` 이 인라인 스타일로 세팅해 라이트 모드를 덮어쓴다** | `marketColorPreset.ts` 가 `documentElement.style.setProperty` 사용 | 클래스/속성 기반 라이트 테마 규칙이 인라인에 밀려 **등락색만 다크 값으로 남는다.** 게다가 `PRESET_VALUES` 는 프리셋당 1벌인데 새 시스템은 프리셋×모드 **4벌**을 요구한다. 차트도 생성 시 한 번만 변수를 읽어 모드 전환 시 재색칠되지 않는다 |
| F8 | **`darkMode` 설정이 없는데 Auth 3파일이 `dark:` 유틸리티를 쓴다** | `tailwind.config.mjs` 에 `darkMode` 없음 → OS 설정을 따름. `Signup.tsx`·`Signupinfo.tsx`·`Agreettac.tsx` | 라이트 모드를 토글로 넣으면 **토글과 OS 설정이 서로 다른 화면을 만든다** |
| F9 | **봇 설정에 변경 이력이 없다** | 전략은 파일(git diff 가능)이지만 봇은 DB 행 | 손절선을 -7% → -5% 로 바꾸는 순간 그 봇의 누적 성과는 **존재한 적 없는 봇의 것**이 된다. 실험 플랫폼에서 치명적이다 |
| F10 | **미가동 구간 개념이 어느 문서에도 없다** | 로컬 배포판 = 각자 자기 컴퓨터 | **노트북을 닫으면 봇도 멈춘다.** 장중 4시간 절전이면 그날 시그널이 통째로 비는데 누적 수익률은 그 사실을 모른 채 계산된다. 백테스트와 실운용이 벌어지는 최대 원인이 될 수 있다 |

> F6·F7·F8 은 **토큰 구현 1단계 안에서 닫힌다** — 별도 이슈가 아니라 그 작업의 완료 조건이다.
> F9·F10 은 실험 플랫폼이라는 제품 정의(§0.1)와 직결되므로 **이슈 승격 후보**다. F1 과 함께 리드가 판단한다.

> F1 만 **이슈로 승격할 후보**다 — 이번 디자인 작업에서 안 닫히고, 백엔드 계약 변경이라 독립적으로 계획·구현·검증될 만큼 크다. 나머지 넷은 구현 작업 안에서 닫히거나(F2·F3·F4) 이미 계획에 있다(F5). **승격 여부는 리드가 판단한다.**

## 5. 아직 안 그린 화면

솔직히 남긴다. 이번 세션에서 **그리지 않은 것**이다.

- **스크리너 조건 편집** — 유니버스를 만드는 화면. 봇 만들기의 「후보 풀」이 여기서 온다
- **저녁 리포트** — 배치 산출물을 읽는 화면. 브리핑이 요약을 보여주고 여기로 이어진다
- **패널 8종의 내부** — 호가·수급·뉴스·공시·리서치 근거·AI 콘솔·포지션·동종업계. **데이터 계약이 있는 것부터** 그릴 수 있다
- **모바일·좁은 화면** — 이 제품은 데스크톱 지휘소지만, 브리핑만이라도 좁은 화면에서 읽을지 정해야 한다
