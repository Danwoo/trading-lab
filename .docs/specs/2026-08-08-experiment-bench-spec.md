## 0. 결론

**화면 명세가 엔진 스키마를 결정한다.** 이 문서는 화면 시안이 아니라 그 역산이다.

현재 제약을 먼저 못박는다 — 실측이다.

| 사실 | 근거 |
|---|---|
| **백테스트 엔진이 코드 0줄이다** | `backtest`·`strategy`·`slippage`·`commission`·`fill_price` grep 결과 구현 0건(주석 3곳). `app/modules.py` 라우터 11개에 backtest/strategy/bot 없음 |
| **시세 적재본이 0행이다** | `tn_instrument`·`tn_daily_bar`·`tn_minute_bar`·`tn_ingest_run` 전부 0. 키가 비어 있고 `USE_REAL_API=false` |
| **`tn_nav` 는 자산곡선 대체가 안 된다** | `nav_producer_manager.py` 가 `nav`·`drawdown` 을 **서로 독립인 랜덤워크**로 생성. 일봉이 아니라 36초 간격 틱이고 조회 API 상한이 48시간 |

> 그래서 이 명세는 **지금 만들 화면의 도면이 아니라, 엔진과 화면을 동시에 짜기 위한 계약**이다.
> 순서는 명세 → 엔진(§6 테이블) → 적재 → 화면이다.

|---|---|---|

| 2 | 드로우다운 곡선(언더워터) | 얼마나 깊게, **얼마나 오래** 물려 있었나 |

## 1.5 판정 절차 — 지표가 아니라 순서 있는 게이트다

실무의 판정은 "지표가 좋은가"가 아니라 **게이트를 순서대로 통과하는가**다. 화면은 이 순서를 그대로 드러내야 한다.

```
① 무결성 (체결·데이터·비용 가정이 말이 되나)  ← 여기서 대부분 즉사
② 표본 충분성 (거래 수 · 기간 · 시도 횟수 대비 데이터 길이)
③ 다중검정 보정 (DSR · haircut SR) — 시도 횟수 N 없이는 판정 불가
④ 시간축 검증 (purged walk-forward · CPCV) — 폴드별 통과율 + 치명적 거부권
⑤ 파라미터 안정성 (고원 vs 봉우리 · cliff veto)
⑥ 잠금 후 홀드아웃 (no further tuning)
⑦ 인큐베이션 → 소액 실전 → 증액
```

### 1.5.1 D13 과 충돌하지 않는다 — 오히려 이것이 D13 의 구현이다

**D13 결정은 "도구가 판정하지 않는다"였다.** 문헌이 권하는 것은 시스템이 정한 합격선이 아니라 **사용자가 미리 확약한(pre-committed) 합격선**이다. 요점은 임계값의 출처가 아니라 **결과를 본 뒤에 임계값을 바꾸지 않는 것**이다.

> 화면이 해야 할 일 — 사용자가 **실행 전에** 기준을 쓰게 하고, **실행 후에 그 기준이 바뀌면 그 사실을 기록**한다. 잠그지는 않는다.

### 1.5.2 판정은 3택이다 — 어디서 떨어졌느냐가 처분을 정한다

**Deploy / Reject / Refactor.** 파라미터 안정성에서 떨어지면 설계를 다시 짜야 하고(Refactor), 검증 단계에서 떨어지면 버린다(Reject). 같은 "실패"가 아니다.

**치명적 거부권(catastrophic veto)** — 낙폭 무결성 붕괴나 제약 위반이 **한 폴드라도** 나오면 평균이 아무리 좋아도 즉시 FAIL. 평균으로 덮이지 않는다.

### 1.5.3 시도 횟수 없이는 아무것도 판정할 수 없다

> **"시도 횟수 N 을 보고하지 않은 연구자는 과적합 위험을 평가하는 것 자체를 불가능하게 만든다."**
> — Bailey·Borwein·López de Prado·Zhu, *Notices of the AMS* 61(5), 2014

그래서 **N 은 부가 정보가 아니라 1급 데이터**다. §6 의 `attempt_no` 컬럼이 여기 걸려 있다.

**MinBTL — 표본이 시도 횟수를 감당하는가**

| 데이터 길이 | 독립 시도 상한 |
|---|---|
| 2년 | **7회** |
| 5년 | **45회** |

그 이상 시도하면 *IS Sharpe 1 · OOS 기대 Sharpe 0* 짜리를 만들어낼 것이 사실상 보장된다. **필요조건이지 충분조건은 아니다.**

### 1.5.4 과적합 진단 4종 — 화면에서 무엇으로 보이나

| 진단 | 기각 기준 | 화면 |
|---|---|---|
| **PBO** (IS 1등이 OOS 중앙값 아래로 갈 확률, CSCV) | **PBO > 5% 기각** | logit 히스토그램 + 5% 임계선. 실측 대비 — 나쁜 예 **74%**(IS Sharpe 전부 양수인데 OOS 의 78%가 음수), 좋은 예 **0.04%** |
| **성능 열화** | 회귀 기울기 β 가 대개 음수 | (IS SR, OOS SR) 산점도 + 회귀선 |
| **DSR** (시도 다중성에 맞춰 임계를 올린 Sharpe) | 95% 신뢰수준 미달이면 거절 | **SR 과 DSR 을 나란히** + 입력 5개(N · V[SR] · T · 왜도 · 첨도) 노출 + **N-민감도 곡선** |
| **haircut SR** (다중검정 보정) | Bonferroni / Holm / BHY 3값 | **"50% 일괄 할인"은 틀렸다 — 보정은 비선형**이다. 높은 Sharpe 는 적게, 한계 Sharpe 는 크게 깎인다 |

> **DSR 실례**: 연 Sharpe 2.5, 일별 5년(T=1250), **N=100** → DSR ≈ **0.90 → 거절**.
> 같은 전략을 **N=46** 에서 발견했다면 DSR 0.9505 로 **통과**였다. **숫자는 그대로인데 판정이 뒤집힌다** — 시도 횟수가 판정 자체를 바꾼다.
>
> 그리고 **PBO 와 "OOS 손실확률"은 별개**다. PBO≈0 인데도 그냥 못 버는 전략일 수 있으므로 두 배지를 따로 둔다.

### 1.5.5 파라미터 안정성 — cliff veto

- **고원**: `Ω_stable = {θ : SR(θ) ≥ α·SR_opt}`, 기본 α = 0.9
- **절벽**: 이웃을 격자 ±1칸으로 잡고 `Cliff_SR(θ) = max[SR(θ) − SR(θ')]₊`, `Cliff_DD(θ) = max[MDD(θ') − MDD(θ)]₊`
- **기각**: `Cliff_SR > τ_SR` 또는 `Cliff_DD > τ_DD`

목적은 *"good but thin"*(얇은 봉우리)을 제거하고 **두께 있는 고원**을 고르는 것이다. 화면은 3D 표면이 아니라 **히트맵 + 선택점 마커 + cliff 수치 배지**로 낸다.

### 1.5.6 체결 현실성 — 단일 판정식

```
C_max = (Σ 거래별 손익) / 거래 수        ← 흡수 가능한 비용 쿠션
C_max < 실측/가정 왕복비용(스프레드+수수료+슬리피지)  →  execution-fragile
```

화면은 **"거래당 평균 수익 vs 왕복 비용" 단일 막대**(쿠션 배수)와 **슬리피지 스윕**(0·5·10·20·50bp 오버레이) + **"Sharpe 가 0 이 되는 손익분기 슬리피지 ○bp"** 로 낸다.

### 1.5.7 탈락 신호 (red flag) — 무결성 7종

| 죄 | 화면이 잡는 법 |
|---|---|
| 생존편향 | 유니버스 히스토리 + **상장폐지 포함 여부** 플래그, 시점별 종목 수 추이 (**D11 이 이걸 닫는다**) |
| 미래참조 | 데이터별 **"공시 시점 vs 사용 시점" 지연 표** |
| 사후 서사 | 가설 등록 시각 vs 데이터 관측 구간 타임스탬프 |
| 데이터 스누핑 | 시도 카운터 + PBO/DSR |
| 회전율·비용 | 비용 0/실측/2배 커브 3중 오버레이 |
| 이상치 의존 | **상위 1%·5% 거래 제외 시 재계산** (R11) |
| 대차 비용 | 숏 종목의 대차 가능·차입비용 커버리지 % |

추가로 — **수익 집중도(HHI)**, **종목별 PnL 기여 + 상위 5개 누적 비중**, **거래/일**(총 거래 수와 별도. *"드물게 거래해서 나온 좋은 성과"* 를 잡는 지표), **95퍼센타일 낙폭**, **최장 미회복 기간**.

### 1.5.8 모의 → 실전 승격 시 추가로 보는 것

| 항목 | 내용 |
|---|---|
| **MinTRL** | 트랙레코드가 통계적으로 충분한가. 예 — 월간 136관측·연 Sharpe 1.0·벤치 0.75·95% → **MinTRL 184개월**, 즉 **4년 더 필요** |
| **Implementation Shortfall** | 의도가 vs 실제 체결가를 **delay / execution / opportunity** 3분해 |
| **Capacity** | 얼마까지 굴릴 수 있나. LEAN 은 해상도별 시장거래량 참여 가정(일봉 2% · 분봉 20%)을 쓰고 **가장 비유동적인 종목** 기준으로 포트폴리오 용량을 잡는다 |
| **상태 누출** | 경로의존 전략은 테스트 창 진입 시 **포지션 flat·카운터 초기화** |
| **인큐베이션** | 실시간 무자본 관찰 후 소액 실전 → 증액 |

> **시장충격은 단일 법칙으로 확정하지 않는다** — 제곱근 법칙이 널리 쓰이나 로그 의존이 더 맞는다는 반론이 있다. 용량 추정은 가정을 화면에 명시하고 사용자가 바꿀 수 있게 한다.

### 1.5.9 화면 탭 구성 (판정 절차를 그대로 반영)

| 탭 | 담는 것 |
|---|---|
| **0. 출처·시도** | 시도 횟수 N · 데이터 길이 vs MinBTL 게이지 · 실행 감사 로그 |
| **1. 게이트** | IS→WFA→OOS 진행바 · 사전확약 임계값 표 · **Deploy/Reject/Refactor** 배너 · veto 램프 |

| **3. 안정성** | 파라미터 히트맵 + 선택점 · **Cliff_SR/Cliff_DD** · 폴드별 OOS Sharpe + 통과율 |

> **주의 — 숫자를 그대로 옮기지 않는다.** 위 게이트 골격의 상당 부분은 2026-03 프리프린트 한 편(단일 통화쌍·이상적 체결 가정)의 사례에서 왔다.
> **골격(게이트·purge·cliff veto·다수결 통과)은 인용할 만하나 임계값(SR≥2.0 · MDD<7% · q=2/3 · α=0.9)은 그 사례의 선택이지 업계 표준이 아니다.**
> PBO 5%·MinBTL·DSR·haircut 은 1차 문헌 원문에서 확인된 것이라 등급이 다르다.

## 2. 인터랙션 명세 — 무엇을 누르면 무엇이 답해지는가

**이전 시안이 기각된 이유는 차트가 부족해서가 아니라 조작이 상태를 바꾸지 않았기 때문이다.** 조작이 자기 패널 안에서 끝나면 그것은 정보 나열이다.

### 2.1 최소 조건 셋

1. **모든 조작이 공유 선택 상태를 바꾸고, 그 상태가 다른 패널을 필터한다** (brushing & linking)
2. **모든 실행 결과는 불변 스냅샷이고, 비교·되돌리기는 그 위에서만 성립한다**
3. **응답 예산을 먼저 정하고, 그 예산이 가능한 조작만 실시간으로 만든다**

### 2.2 조작 → 반응 → 질문 → 결정

| # | 조작 | 화면 반응 | 답해지는 질문 | 내려지는 결정 |
|---|---|---|---|---|
| R1 | 자산곡선에서 낙폭 구간 드래그 | 거래목록·보유·종목별 기여도·비용이 **그 구간으로 필터**, 지표 재계산. 브러시는 URL 에 직렬화 | 이 낙폭이 한 종목 때문인가 시장 전체인가 | 종목 집중이면 배분 상한 추가 / 시장이면 노출도 문제로 분류 |
| R2 | 최악 낙폭 표의 한 행 클릭 | 곡선에 peak~recovery 음영 + R1 과 같은 필터. 회복 소요일수 강조 | 최악 구간이 언제였고 얼마나 오래 물렸나 | 회복기간이 견딜 수 있는 길이를 넘으면 레버리지·보유기간·손절을 바꾼다 |
| R3 | 거래 목록의 한 행 클릭 | 종목 차트가 **그 진입/청산 봉으로 스크롤**, 그 시점 신호 근거(팩터 값·조건 통과) 표시 | 이 거래는 규칙대로 난 것인가 **데이터 오류로** 난 것인가 | 오류면 데이터 보정으로, 규칙 문제면 조건 수정으로 분기 |
| R4 | 파라미터 슬라이더 드래그 | 사전계산 격자에서 해당 조합이 즉시 교체, 직전 값이 **고스트 선**으로 잔류 | 성과가 그 값에 민감한가 — **절벽인가 고원인가** | 절벽이면 기각(우연), 고원이면 **고원 중앙값** 채택 |
| R5 | 파라미터 히트맵 셀 클릭 | 그 조합의 리포트가 **비교 슬롯 B** 에 로드(A 유지) | 최고점이 고립된 점인가 이웃도 좋은가 | 고립점이면 과적합으로 폐기 |
| R6 | 실험 둘을 "겹쳐 보기" | 곡선 겹침 + 파라미터·지표 표가 **다른 값만 표시(diff only)** | 무엇이 달라져서 성과가 달라졌나 | 원인 후보 하나만 남기고 재실행 — 변수 통제 |
| R7 | 기준선 고정(실계좌·벤치마크) | 모든 차트에 상시 겹침, 지표가 **절대값 → 초과분(Δ)** 표기로 전환 | 절대 수익이 아니라 **초과 성과**가 있나 | 초과가 없으면 채택하지 않는다 |
| R8 | 워크포워드 분할점 슬라이더 | IS/OOS 경계 이동, 두 구간 지표 갱신. 분할점별 OOS 성적이 분포로 누적 | 성과가 **특정 분할에서만** 나오나 | 민감하면 승격 보류하고 표본을 늘린다 |
| R9 | 유니버스 as-of 날짜 스크럽 | 그 시점 상장 종목·그때 공시된 재무만 남음. **"제외된 종목 N개" 배지** | 이 결과가 생존편향인가 | 편향이 확인되면 유니버스 정의를 시점 기준으로 다시 잡는다 |
| R10 | 팩터 기여도 막대 클릭 | 그 팩터 상·하위 종목과 종목별 기여 열림 | 수익이 **팩터에서** 왔나 **한 종목에서** 왔나 | 한 종목이면 "이 팩터가 통한다"는 주장을 철회한다 |
| R11 | 거래 산점도에서 이상치 lasso → "이 표본 제외" | 지표 전체 재계산, 원래 값이 취소선으로 병기 | 상위 1% 거래를 빼면 전략이 남는가 | 안 남으면 기각(운 의존) |
| R12 | 비용 슬라이더(수수료·슬리피지·체결지연) | 지표 재계산 + **손익분기 비용 눈금**이 슬라이더 위에 표시 | 얼마의 비용까지 살아남나 | 실제 비용이 손익분기 근처면 기각 |
| R13 | 패널의 "구간 링크 해제" 토글 | 그 패널만 전역 브러시를 무시하고 자기 기간 유지 | 전파된 필터 때문에 **못 보고 있는 대조군**이 있나 | 국소 비교 후 다시 링크를 켠다 |
| R14 | "32번째 시도" 배지 클릭 | 같은 계보 조합 전체와 성적 분포, **현재 결과가 분포의 어디인지** | 이 샤프가 실력인가 **N번 중 최댓값**인가 | 분포 최댓값 자리면 승격 보류 |
| R15 | 숫자에 hover | 출처 · `adj_policy` **원값 그대로** · 갱신 시각 · 임시데이터 여부 | 이 숫자를 믿어도 되나 | 미보정 구간이 섞였으면 그 구간 결론을 유보 |
| R16 | 리더보드 "신뢰구간 보기" 토글 | `1.14 ±0.54` 표기, **구간이 겹치는 행은 동순위로 묶임** | 1등이 통계적으로 1등인가 | 구분이 안 되면 순위로 고르지 않고 다른 축으로 고른다 |
| R17 | 실험 이력 그래프의 과거 노드 클릭 | 그 시점의 **뷰 상태 전체** 복원, 거기서 조작하면 **새 가지** 생성 | 그때 무엇을 보고 그렇게 판단했나 | 다른 가지로 재시도하고 R6 으로 비교 |
| R18 | "미가동 구간 표시" 토글 | 봇이 안 돌던 구간 음영 + "그 구간 제외 시" 성과 병기 | 백테스트-실운용 괴리가 **전략 탓인가 가동 탓인가** | 가동 탓이면 전략을 고치지 않고 인프라 문제로 분류 |

> **R1·R2·R5·R13 은 상용 퀀트 제품의 실물 전례를 확인하지 못했다.** 범용 분석도구(Grafana·Tableau·crossfilter·W&B)의 검증된 패턴을 이 도메인에 이식한 설계다. TradingView 는 반대 방향(목록 → 차트 이동)만 확인된다.

### 2.3 전파 규칙

**필터는 기본 전파, 해제는 패널 단위 명시 조작(R13).** 화면 *간* 문맥 전파 규칙(D8)과 같은 원리를 화면 *안*에도 적용한다 — 기본 전파 + 해제 가능한 칩.

## 4. 되돌리기와 비교

### 4.1 두 종류를 가른다

| | 뷰 상태 되돌리기 | 실행 되돌리기 |
|---|---|---|
| 대상 | 브러시·필터·기간·비교 슬롯·정렬 | 파라미터 변경·데이터 버전 변경 |
| 구현 | URL 히스토리 + 분기 그래프 | **되돌리지 않는다 — 새 run 을 만든다** |

**run 은 불변이고 파라미터 편집은 항상 fork 다.** 실험 도구에서 "저장"이 아니라 "실행"이 커밋에 해당한다.

> 이것이 **D2(봇 만들기에 저장 버튼 없음)** 결정이 성립하기 위한 전제다 — 실행 시점 스냅샷이 반드시 남아야 한다.
> 그리고 **F9(봇 설정에 변경 이력 없음)** 를 함께 닫는다. 이력이 없으면 §2 의 비교 행(R6·R14·R17)이 전부 거짓말이 된다.

### 4.2 비교 표현 3형식

| 형식 | 쓰는 자리 | 규칙 |
|---|---|---|
| **겹쳐(superposition)** | 자산곡선·낙폭곡선 | 최대 2~3개. 기준선은 저채도, 현재 run 이 앞에 |
| **나란히(juxtaposition)** | IS/OOS · 연도별 · 워크포워드 | **축 범위를 강제로 동일**하게 — 다르면 나란히 둘 의미가 없다 |
| **차이 자체(explicit encoding)** | 파라미터·지표 표 | **diff only 기본 ON** — 동일 값은 접는다 |

## 5. 응답 예산 — 성능이 아니라 제품 기능이다

| 구간 | 예산 | 근거 |
|---|---|---|
| 드래그 중 시각 피드백 | **≤100ms** | 직접 조작감의 한계 (Nielsen) |
| 링크된 뷰 갱신 | **목표 ≤500ms, 상한 1s** | Liu & Heer(InfoVis 2014) |
| 실행·전체 재계산 | **>1s 진행 표시, >10s 완료 예상** | Nielsen |

> **500ms 의 추가 지연만으로 사용자의 관찰·가설 생성 비율 자체가 떨어지고, 높은 지연에 먼저 노출되면 이후 저지연 환경에서도 성능이 떨어진다.**
> 느린 실험대는 불편한 실험대가 아니라 **덜 탐색하는 실험대**다.

**선행 조건**

- 브러시·크로스필터 → 사전 집계 인덱스. 브라우저 내 크로스필터는 100만 행급까지. **전 종목 10년 ≈ 1.5GB 는 그 범위를 넘으므로 DuckDB 계열 위임 또는 사전 집계가 필요하다 — 스파이크로 실측해야 한다**
- 곡선 렌더 → 픽셀 단위 다운샘플(M4 또는 LTTB)
- 슬라이더·히트맵 → **격자 사전계산.** 슬라이더는 계산이 아니라 조회여야 한다

**즉시 반응이 불가능할 때** — ① 조작 모델을 슬라이더에서 **실행 큐(제출형)** 로 바꾼다 ② 부분 결과를 흘린다 ③ 근사 먼저 + 정밀 나중(오차범위 배지 병기 — FR-020 의 임시데이터 배지와 같은 원리) ④ debounce 를 명시 ⑤ 취소 가능하게 하고, 취소해도 이전 결과를 지우지 않는다.

**하지 말 것**: 근사치를 정밀치처럼 보여주기 · 계산 중 이전 결과를 지우고 스피너만 남기기 · 슬라이더를 주고 매 픽셀마다 서버 호출.

## 6. 엔진이 남겨야 할 것 — 화면 요구에서 역산

**이 절이 이 문서의 목적이다.** 위 화면·인터랙션이 성립하려면 엔진이 다음을 기록해야 한다.

| 테이블 | 최소 컬럼 | 무엇을 떠받치나 |
|---|---|---|
| `tn_backtest_run` | `run_id` · `parent_run_id`(계보) · `attempt_no`(시도 순번) · 파라미터 값 · 유니버스 정의와 as-of 규칙 · 데이터 스냅샷 식별자 · `adj_policy` · 비용 가정 · 전략 버전 · 실행 시각 | R6(diff) · R14(시도 횟수) · R17(이력 복원) · §4.1(불변 스냅샷) |
| `tn_backtest_equity` | `run_id` · `dt` · `equity` · `cash` · `position_count` · `gross_exposure` | 1(자산곡선) · 2(낙폭) · 3(월별) · 4(롤링) · 7(포지션·현금) |
| `tn_backtest_trade` | `run_id` · `instrument_id` · `side` · `entry_ts` · `exit_ts` · `qty` · `fill_price` · `fee` · `slippage` · `realized_pnl` · `mae` · `mfe` | 5(거래통계) · 6(거래목록) · 8(종목별 기여도) · MAE/MFE · R3 · R11 |
| `tn_backtest_signal` | `run_id` · `dt` · `instrument_id` · 조건별 통과 여부 · 팩터 값 | R3(신호 근거) · R10(팩터 기여도) |

**현금 원장은 별도로 초기자금·입출금 이벤트를 기록해야** 현금 비중이 닫힌다.

> **계보(`parent_run_id`)와 시도 순번(`attempt_no`) 두 컬럼이 R6·R14·R17 을 동시에 떠받친다.**
> 이게 없으면 "무엇이 달라졌나"도 "몇 번째 시도인가"도 계산할 수 없다.

**스윕 러너 설계 규칙 (실측 근거)**

```
throughput 9.84M bars/s (단일 코어, 순수 파이썬 · 하한)

20×20=400조합 · KR 전종목 10년(686만 bar)
  로드 1회 + 인메모리 400회  →  약 4.9분
  조합마다 DB 재조회         →  약 83분     ← I/O 가 계산의 16배
```

- **"로드 1회 + 인메모리 N회"가 강제 규칙이다.**
- `backend-service` 에 numpy·pandas 가 없다. 순수 파이썬이면 **컬럼 지향(SoA) 필수** — 686만 행에서 행 지향 1.81GB vs 컬럼 지향 0.35GB.
- 위 수치는 단일 시계열 SMA 루프 기준 **하한**이다. 다종목 랭킹·포지션 사이징·현금 원장·리스크 룰이 붙으면 bar 당 5~20배 느려지는 것이 보통이라, 현실은 20분~1시간대로 본다. 결론(계산이 아니라 로딩·메모리가 병목)은 뒤집히지 않는다.

## 7. 실현 가능성 — 두 갈래

**A그룹 — 엔진 + 적재만 하면 열린다** (새 소스 조사 불필요)
자산곡선·낙폭 · 월별 히트맵 · 롤링 샤프 · 파라미터 민감도 · 거래목록·분포 · 포지션/현금 · 종목별 기여도 · 체결가정 민감도

**B그룹 — 새 데이터 소스 조사부터** (병렬 착수 가능, 리드 타임 김)

| 항목 | 막고 있는 것 |
|---|---|
| **벤치마크 겹치기 (시장 지수)** | **지수 시계열 축이 파이프라인에 없다.** `MarketDataProvider` 에 지수 메서드 없음, `DataKind` 에 `index` 없음, MCP `market_index` 는 **스칼라 1점**이며 **코스피200이 없다** |

> **D-Q3·D-Q4 로 B그룹이 하나 줄었다.**
> **동일가중 유니버스**는 적재본에서 계산하므로 새 소스가 필요 없고, **섹터 노출**도 상관 클러스터링으로 대체해 A그룹으로 내려왔다.
> 남은 B그룹은 **시장 지수 하나**이며, 그것도 없으면 동일가중 유니버스만으로 상당 부분이 답해진다.

**지금 당장 만들 수 있는 화면** (백테스트가 아닌 것) — 적재 상태(`tn_ingest_run` + `BarService.find_gaps`) · 소스 가용성 표(`capability_router`) · 캔들 차트(`bar_router` + `ChartPanel`, 지금은 `unavailable_reason` 만 표시).

## 8. 결정 — 트레이더 기준으로 확정 (2026-08-08)

일곱 항목 모두 **"만들기 쉬운 쪽"이 아니라 "트레이더가 실제로 판단하는 순간"** 을 기준으로 정했다. 각 항목의 첫 안(보수적 안)과 무엇이 달라졌는지 함께 남긴다 — 나중에 되돌아볼 때 근거가 필요하다.

### D-Q1. 단일 결과를 만들지 않는다 — 실행이 곧 격자 실행

퀀트는 "이 파라미터의 성과"를 궁금해하지 않는다. **"이 성과가 그 파라미터에만 붙어 있나"** 를 궁금해한다.

```
첫 안:   실행 → 결과 1개 → (원하면) 민감도 맵
확정:    실행 → 결과가 처음부터 이웃 격자        ← 단일 점은 존재하지 않는다
```

- 후보풀 200종목 · 400조합이 **약 20초**다. 매번 돌려도 된다.
- **점 하나를 보여주는 화면을 만들지 않으면 과적합이 구조적으로 어려워진다** — 봉우리에 걸터앉은 것을 숨길 데가 없다.
- 전 종목은 **고원 중앙값을 찾은 뒤 확인 사격**용으로만 쓴다.

> 파라미터 조작 모델(슬라이더 vs 제출형)은 이 결정의 하위 문제가 된다 — 격자가 이미 있으므로 격자 축은 슬라이더(조회), 격자 밖은 제출형이다.

### D-Q2. 샤프를 1급 지표에서 내리고 최장 미회복 기간을 올린다

**트레이더가 계좌를 닫는 이유는 샤프가 낮아서가 아니라 낙폭을 못 견뎌서다.** 대표 지표 순서를 그 사실에 맞춘다.

| 순위 | 지표 | 실제로 묻는 것 |
|---|---|---|
| 1 | **최장 미회복 기간** | 몇 달을 물려 있어야 하나 |
| 2 | **MDD + Calmar** | 내가 견딜 수 있는 크기인가 |
| 3 | **거래당 평균 수익 vs 왕복 비용**(C_max) | 비용 먹고도 남나 |
| 4 | 연환산 수익률 | 얼마 버나 |
| 5 | 샤프 | 참고용 |

> **MDD 와 최장 미회복 기간은 다른 정보다.** MDD -22% 는 숫자로 견딜 만해 보이지만 그것이 14개월 지속됐다면 대부분 중간에 끈다.
> 조사한 도구 대다수가 MDD 만 크게 보여주고 지속 기간은 표 안에 묻어 둔다 — 우리는 반대로 놓는다.

**무위험수익률은 0 고정 + 화면 명시로 끝낸다.** 모든 봇에 같은 값이면 순위가 바뀌지 않으므로 논쟁 가치가 낮고, "지수보다 나은가"는 D-Q3 이 답한다.

### D-Q3. 벤치마크는 복수 — 기본에 「동일가중 유니버스」를 넣는다

코스피200 겹치기만으로는 **가장 중요한 질문에 답을 못 한다.**

```
내 전략 +18%  ·  코스피200 +9%              →  "이겼다"
그런데 내 유니버스 동일가중이 +17% 였다면?
  →  종목을 고른 능력이 아니라 그 유니버스가 좋았던 것
```

**기본으로 항상 겹치는 것 둘** — ① 시장 지수(코스피200 등) ② **내 유니버스 동일가중**. 세 번째로 **내 실계좌**를 사용자가 고정할 수 있게 한다(R7).

**저장은 별도 테이블**로 간다. 이유가 둘이다 — ㉠ 유니버스에 지수가 섞이면 "전 종목 스캔"에 지수가 매수 후보로 올라온다 ㉡ **동일가중 유니버스는 계산해서 만드는 계열**이라 애초에 종목 테이블에 넣을 수 없다.

### D-Q4. 업종을 사오지 말고 상관 클러스터링으로 만든다

**팩터 전략은 대부분 의도치 않은 섹터 베팅으로 판명난다.** 저PBR 전략이 실제로는 금융·건설·조선 몰빵인 식이다. 이걸 모르면 자기 전략이 무엇인지 모르는 것이므로 **나중에 할 일이 아니다.**

| | 판단 |
|---|---|
| GICS | 국제 표준이지만 **유료** |
| KRX 업종분류 | 무료지만 국내 전용, 미국과 체계가 다름 |
| **상관 클러스터링** | **무료 · 데이터가 이미 있음 · 국내·미국 동일 방식** |

그리고 더 실전적이다 — 같은 업종이어도 안 붙어 다니는 종목이 있고, 다른 업종인데 같이 무너지는 종목이 있다. 트레이더가 알고 싶은 것은 **"같이 무너지는 종목끼리 얼마나 들고 있나"** 지 산업 분류표가 아니다.

화면 표기는 **"3개 클러스터에 82% 집중"** + 클러스터별 대표 종목명.

> 이 결정으로 §7 B그룹에서 「섹터 노출」이 빠진다. 새 데이터 소스 확보가 불필요해졌다.

### D-Q5. 판정 기준을 가설이 아니라 계정에 붙인다

"바꾸면 기록한다"는 사후 처방이다. 트레이더가 원하는 것은 **도구가 자기 규율을 지켜주는 것**이다.

```
첫 안:   가설마다 기준을 새로 쓴다   →  매 실험이 자기 합격선을 데리고 온다 = 변명
확정:    내 기준은 하나다            →  모든 가설을 같은 자로 잰다
```

기준을 바꾸면 **그 이후 모든 실험에 적용**되고, 이전 판정 이력에는 *"기준 v2 로 재평가하면 이 봇은 탈락"* 이 보인다. 훨씬 아픈 피드백이고 그래서 효과가 있다. **여전히 차단하지 않는다(D13).**

### D-Q6. 공짜 지표는 상시, 비싼 검사는 요청 시

"승격 직전에 PBO 를 돌린다"는 늦다. **실험을 100번 하고 나서 과적합이라고 알려주면 이미 100번을 버린 것이다.**

| 층 | 항목 | 비용 |
|---|---|---|
| **상시** | 시도 횟수 N · **MinBTL 대비 게이지** · IS/OOS 격차 · 고원 두께 | 공짜 (격자를 이미 돌렸으므로) |
| **요청 시** | PBO · DSR · haircut SR | 약 10분 (CSCV 12,780 조합) |

> **MinBTL 게이지가 상시로 붉어지는 것이 핵심이다** — *"5년 데이터에 45회가 상한인데 지금 62회"* 가 62번째에 보이면 100번까지 가지 않는다.

### D-Q7. 단계를 늘리지 말고 경과일수와 괴리를 최상단에 놓는다

인큐베이션의 본질은 단계 이름이 아니라 **시간이 지나야 드러나는 것들**이다. 우리 모의 운용이 이미 실시간·무자본이라 실질적으로 같다.

**모의 운용 화면 최상단 한 줄로 대신한다:**

```
모의 운용 47일 · 백테스트 대비 괴리 -1.2%p · 미가동 3일 · 미체결 4건
```

그리고 승격 버튼 옆에 **MinTRL** 로 *"통계적 판단까지 앞으로 11개월"* 을 붙인다. 트레이더는 "인큐베이션 단계입니다"라는 라벨이 아니라 **"47일 돌렸고 -1.2%p 벌어졌다"** 는 사실을 원한다.

> 「미가동」은 F10 을 함께 닫는다 — 로컬 배포판이라 노트북을 닫으면 봇도 멈추는데, 그 사실이 지금 어느 문서에도 없다.

## 8.5 페르소나 검증 (2026-08-08)

화면을 만든 뒤 **리드에게 보이기 전에** 네 페르소나에게 먼저 검증받았다. 넷이 서로 다른 층을 짚었고 넷 다 유효했다.

| 페르소나 | 「딱 하나만 고친다면」 | 층 |
|---|---|---|
| 감으로 매매하던 40대 (퀀트 처음) | 수익 옆에 **같은 크기로** "우연일 수 있습니다" | 시선 |
| 자동매매로 원금 30% 잃어본 트레이더 | **내가 정한 손실 한계선과 남은 거리** | 규율 |
| 오픈소스를 클론한 개발자 | 전 화면에 **고정 모드 배지** | 안전 |
| 직접 백테스트를 짜본 퀀트 | **비용·체결·유니버스 가정을 화면에 상주** | 신뢰 |

> 넷 다 "수익이 크고 경고가 작다"를 지적했다. 40대의 말이 가장 아팠다 —
> *"bot-live 는 원래 저를 말리려고 만든 화면 같은데, 저는 못 알아들어서 안 말려집니다. **설계 의도랑 결과가 반대로 갑니다.**"*

### 8.5.1 계산 정의 — 버그로 드러난 것을 규칙으로 승격

퀀트 페르소나가 프로토타입 코드를 떼어 실행해 검산했다. **엔진 구현 시 반드시 지킬 정의다.**

| 항목 | 잘못된 구현 | 올바른 정의 |
|---|---|---|
| **낙폭 금액** | `원금 × MDD` | **`그때의 고점 평가액 × MDD`** — 원금에 곱하면 체계적 과소(실측 36%) |
| **언더워터 기간** | 「원금 회복까지」 | **「전 고점 아래에 머문 최장」.** 원금과 무관하다. 끝에서 미회복이면 **"아직 회복 중"** 명시 |
| **연환산(CAGR)** | 구간 길이와 무관하게 환산 | **표본이 짧으면 환산하지 않는다.** 26일 구간을 연환산하면 57.8%가 나온다. 최소 길이 미만은 **구간 총수익률만** |
| **구간 낙폭** | 브러시 시작을 고점으로 리셋 | 구간 밖의 직전 고점을 이어받는다 |
| **매매 빈도** | 조건 0개에도 매매 발생 | **매수 조건이 없으면 매매도 없다.** 그리고 **빈 슬롯 수를 넘는 매수는 불가능** |
| **거래비용** | 위탁수수료 0.15% | **0.015% 수준(왕복) + 증권거래세(매도만).** 10배 오차가 "연 비용 원금의 145%" 경고를 만들었고, **첫 화면부터 뜨는 경고는 경고를 무시하는 법을 학습시킨다** |

### 8.5.2 다중검정 장치의 자기모순

화면이 **"설정 100가지를 전부 돌려봤습니다"** 라면서 **"45번까지가 한계"** 라고 경고했다. **100 > 45** 다. 게다가 격자 클릭이 시도 횟수를 안 올려, 100칸을 훑어 최고점을 골라도 *"앞으로 13번까지는 믿어도 됩니다"* 라고 말했다.

> **규칙**: 사용자가 **처음 평가하는 조합마다 시도 횟수가 오른다.** 격자를 훑는 것도 시도다.

### 8.5.3 「없는 계산을 한 척하는 값」 금지

프로토타입의 `수수료 여유 3.4배` · `3종목 48%` · `6조각 중 5조각` 은 전부 **격자 품질값의 1차식**이었다. 거래도 곡선도 계산에 안 들어갔다.

> *"근거 없이 정밀한 숫자는 근거 없이 뭉뚱그린 숫자보다 나쁩니다."*

**규칙 — 유도 경로가 없는 숫자는 화면에 올리지 않는다.** 표시하려면 **무엇에서 유도됐는지를 값 옆에 적는다.**

### 8.5.4 안전 표시

전 화면 HUD 왼쪽에 모드 배지를 고정한다. **한 화면에만 있는 안전 표시는 없는 것보다 나쁘다.**

```
● 모의  실제 주문 나가지 않음 · 연결된 계좌 없음 · 오늘 나간 주문 0건
```

**주문 카운터가 핵심이다** — *"0으로 고정돼 있는 걸 매일 보는 것이 어떤 안내 문구보다 강한 증거가 됩니다."*
그리고 **결과를 모르는 버튼을 돈 화면에 두지 않는다.** 「멈추기」는 누르기 전에 두 선택지를 보여준다.

## 8.6 대화형 플랫폼 (리드 결정 2026-08-08)

**폼만 주면 "무엇을 정해야 하는지 아는 사람"만 쓸 수 있다.** 페르소나 40대가 정확히 거기서 멈췄다 — *"두 개가 체크되어 있고, 저는 이걸 켠 적이 없습니다. 누가 켜놨는지 모르겠습니다."*

**리드 결정: 제안까지 하는 대화를 폼과 병행한다. 이것이 플랫폼의 축이다.**

### 8.6.1 대체가 아니라 병행 — 문이 두 개다

```
왼쪽: 대화                          오른쪽: 폼 (실시간으로 채워짐)
"코스피 대형주 눌림목 봇"      →     시총 3,000억 이상  ← 방금 채워짐
"3,000억이면 후보 214종목입니다"     평균선 20일 눌림   ← 방금 채워짐
"손절은 몇 %로?"                     (아직 비어 있음)
```

**대화가 폼을 채우고, 폼이 대화를 검증한다.** 사용자는 언제든 폼을 직접 고칠 수 있고, 고치면 대화가 이어받는다. 대화만 있고 결과물이 안 보이면 **무엇이 만들어졌는지 모른 채 돈을 건다.**

### 8.6.2 대화는 화면을 가로지른다

대화는 봇 만들기 전용이 아니라 **모든 화면에서 같은 문맥을 읽고 쓴다.** §2 의 brushing & linking 과 같은 원리다 — 조작이 공유 선택 상태를 바꾸듯, 대화도 그 상태를 바꾼다.

| 화면 | 대화가 하는 일 |
|---|---|
| 봇 만들기 | 말을 설정으로 옮긴다 |
| 검증 | 격자·곡선을 가리키며 왜 그런지 답한다 |
| 운용 | "어제 왜 샀어?" → 그 거래로 화면이 이동한다 |
| 스크리너 | 조건을 채운다 |

### 8.6.3 제안의 안전장치 넷

제안을 허용하면 **틀린 조언을 그럴듯하게** 할 수 있다. 막는 방법은 판정 금지가 아니라 **즉시 검증 가능하게** 만드는 것이다.

| 규율 | 내용 |
|---|---|
| **제안은 결과와 함께** | *"-7%를 권합니다"* ❌ → *"-7%면 후보 214종목에서 하루 1.1회 매매, 과거 3년 최악 낙폭 -16.9%"* ✅ |
| **제안하면 바로 돌린다** | 설정이 바뀌면 백테스트가 재실행돼 숫자가 갱신된다. **AI가 틀려도 사용자는 숫자로 본다** |
| **출처가 남는다** | 각 설정에 `내가 정함` / `AI 제안 수락` 표시. run 스냅샷(§6)에 함께 기록 |
| **판정하지 않는다** | D13 그대로 — *"이게 좋습니다"* 가 아니라 *"이렇게 하면 이렇게 됩니다"* |

> **대화도 시도 횟수에 들어간다.** AI 가 설정을 바꿔 재실행하는 것도 §8.5.2 의 다중검정이다. 대화로 열 번 고치면 시도 열 번이다.

### 8.6.4 지표를 수식으로 다룬다 (리드 결정)

합성값 문제의 해법은 지우는 것이 아니라 **진짜 계산으로 바꾸고 지표를 넓히는 것**이다. 그리고 셋은 별개 기능이 아니라 **같은 기계의 세 사용법**이다.

```
모든 지표는 수식이다 — 승률도, 샤프도, 낙폭도.
엔진이 지표를 「내장 목록」이 아니라 「수식」으로 다루면
  ㉮ 미리 만든 수식을 켜고 끈다        (지표 늘리기)
  ㉯ 그 수식의 가정을 연다              (수수료율·기준선을 내 것으로)
  ㉰ 사용자가 새 수식을 추가한다        (내 점수 정의)
```

**지금 정할 것은 순서가 아니라 구조다** — 지표를 하드코딩하면 나중에 ㉰를 못 붙인다. ㉰는 임의 코드가 아니라 **제한된 수식 언어**로 열어 안전 문제를 없앤다.

**스크리너와 같은 기계다.** *"PBR 낮고 ROE 높은 종목"* 도 수식이므로, 하나 만들면 두 곳에서 쓴다.

## 9. 검증하지 못한 것

- **상용 퀀트 제품에 "자산곡선 브러시 → 거래목록 크로스필터"가 실제로 있는지** 확인 못 함. R1·R2 는 범용 분석도구 패턴의 이식이다
- **우리 스택이 §5 예산을 낼 수 있는지** 전혀 측정하지 않았다. 스파이크 필요
- **파라미터 히트맵 셀 클릭 → 리포트 로드**의 전례 확인 못 함(히트맵 생성까지만 확인)
- 젠포트·퀀트킹·Portfolio123 의 결과 화면 구성은 로그인 벽/문서 부재로 **대부분 미확인**
- 백테스트 성능 수치는 **단일 시계열 SMA 루프 기준 하한**이다

## 11. 이 문서를 고치는 방법

**이 명세는 완결된 도면이 아니라 쓰면서 자라는 계약이다.** 실제로 써 보기 전에는 알 수 없는 것이 §9 에 열거된 만큼 남아 있다.

**고칠 때 지킬 것**

- **§8 의 결정을 바꾸면 첫 안과 무엇이 왜 달라졌는지를 함께 남긴다.** 지금 §8 이 그 형식으로 적혀 있다 — 되돌아볼 때 근거가 없으면 같은 논쟁을 다시 한다.
- **§9(검증하지 못한 것)에서 하나를 닫으면 그 줄을 지우고 본문에 사실로 옮긴다.** 미확인 목록이 줄어드는 것이 이 문서의 진척도다.
- **화면을 실제로 써 보고 "이 정보는 안 본다" 싶으면 §1.4(채택하지 않는 것)로 내린다.** 지표를 늘리는 것보다 내리는 것이 어렵고, 그래서 의식적으로 해야 한다.
- **§6 의 테이블 스키마를 바꾸면 그 컬럼을 요구하는 §2 의 조작 행(R번호)을 함께 확인한다.** 계보(`parent_run_id`)와 시도 순번(`attempt_no`)은 R6·R14·R17 세 개를 동시에 떠받치므로 특히 그렇다.

**바뀔 가능성이 높은 자리** — 실제로 써 보면 가장 먼저 흔들릴 곳들이다.

| 자리 | 왜 흔들리나 |
|---|---|
| §1.5.9 화면 8탭 구성 | 탭이 8개면 많다. 써 보면 두세 개로 합쳐질 가능성이 크다 |
| §5 응답 예산 | 우리 스택으로 실측한 적이 없다. 스파이크 결과에 따라 조작 모델(D-Q1)이 다시 갈릴 수 있다 |
| §1.5 게이트 임계값 | 프리프린트 한 편의 사례값이다. 자기 데이터로 돌려 보고 자기 값으로 바꿔야 한다 |
| D-Q4 상관 클러스터링 | 군집 개수·기간·거리 정의를 정하지 않았다. 실제 결과를 보고 정할 문제다 |
