## 사용자 시나리오

우선순위는 **P1 = 이번 베팅(M2)**, P2·P3 = 이후. 각 스토리는 그것만 만들어도 가치가 나오는 단위다.

### 사용자 스토리 1 — 내 화면을 내 손으로 짠다 (P1)

로그인하면 트레이딩 터미널이 열린다. 사이드바에서 종목을 고르면 화면의 모든 패널이 그 종목으로 갈아탄다. 패널을 드래그로 옮기고, 크기를 바꾸고, 안 쓰는 것은 접는다. 그 배치는 다음에 열 때도 그대로다. 워크스페이스를 바꾸면 그 워크스페이스의 배치가 나온다.

**왜 P1 인가**: 이 제품의 형태 자체다. 패널을 붙일 틀이 없으면 어떤 기능도 화면에 못 올라간다. 병렬 개발의 전제이기도 하다 — 틀이 서야 패널을 따로따로 만들 수 있다.

**독립 테스트**: 종목을 바꿔가며 패널이 함께 갈아타는지, 배치를 바꾸고 새로고침해도 유지되는지, 워크스페이스를 전환하면 다른 배치가 나오는지로 검증된다.

**수용 시나리오**:

1. **Given** 로그인한 상태, **When** 사이드바에서 다른 종목을 클릭, **Then** 열려 있는 모든 패널이 그 종목의 데이터로 바뀐다
2. **Given** 패널을 옮기고 크기를 바꾼 상태, **When** 브라우저를 새로고침, **Then** 바꾼 배치 그대로 열린다
3. **Given** 워크스페이스 A 의 배치를 저장한 상태, **When** 워크스페이스 B 로 전환, **Then** B 의 배치가 나오고 A 의 배치는 보존된다
4. **Given** 패널을 닫은 상태, **When** 패널 목록에서 다시 추가, **Then** 그 패널이 화면에 복귀한다

---

### 사용자 스토리 2 — 화면의 숫자가 진짜다 (P1)

종목을 고르면 실제 시세와 재무가 뜬다. 캔들은 우리가 적재해 둔 데이터에서 그려지고, 공시·뉴스도 실제 소스에서 온다. 아직 소스가 연결되지 않은 패널은 **임시 데이터임을 화면에 표시**해서, 무엇이 진짜고 무엇이 아직인지 한눈에 보인다.

**왜 P1 인가**: 가짜 숫자로 채운 화면은 보기엔 완성돼 보이지만 다음 단계(봇·백테스트)를 전혀 지탱하지 못한다. 적재 파이프라인은 이 제품의 나머지 전부가 딛는 바닥이다.

**독립 테스트**: 적재를 돌린 뒤 특정 종목의 캔들이 외부 소스 값과 일치하는지, 임시 데이터 패널에 표시가 뜨는지로 검증된다.

**수용 시나리오**:

1. **Given** 데이터 소스 키를 `.env` 에 넣은 상태, **When** 적재를 실행, **Then** 종목 마스터와 일봉이 로컬에 쌓이고 마지막 적재 시각이 화면에 보인다
2. **Given** 적재가 끝난 상태, **When** 종목을 선택, **Then** 차트가 적재된 캔들로 그려지고 값이 소스와 일치한다
3. **Given** 소스가 연결되지 않은 패널, **When** 그 패널을 열면, **Then** 임시 데이터임이 화면에 표시된다
4. **Given** 해당 시장에 그 데이터가 존재하지 않는 패널(예: 미국 심층 호가), **When** 그 패널을 열면, **Then** "해당 시장은 제공되지 않음"과 이유가 표시된다
5. **Given** 적재 중 소스 한도에 걸린 상태, **When** 적재 상태 화면을 열면, **Then** 어디까지 받았고 무엇이 실패했는지 보인다

---

### 사용자 스토리 3 — 봇을 만들고 과거로 검증한다 (P2)

전략 파일들을 골라 조합하고, 결합 규칙·유니버스·자금 배분·리스크를 정해 봇을 만든다. 만든 봇을 과거 데이터로 돌려 성과를 보고, 여러 봇을 나란히 비교한다.

**왜 P2 인가**: 제품의 핵심 가치지만 P1 의 적재 데이터 없이는 돌릴 수 없다.

**독립 테스트**: 전략 하나로 봇을 만들어 백테스트를 돌리고 성과 지표가 나오는지로 검증된다.

**수용 시나리오**:

1. **Given** 전략 파일이 등록된 상태, **When** 봇 만들기 화면을 열면, **Then** 전략의 파라미터 선언대로 입력 폼이 생성된다
2. **Given** 봇을 만든 상태, **When** 기간을 지정해 백테스트를 실행, **Then** 성과 지표와 함께 사용된 가정(체결 기준·수수료·슬리피지·기간·유니버스)이 표시된다
3. **Given** 봇 여러 개를 백테스트한 상태, **When** 리더보드를 열면, **Then** 위험 지표가 앞에 오는 순서로 전 지표가 표시되고 열 클릭으로 정렬을 바꿀 수 있다

---

### 사용자 스토리 4 — 봇이 장중에 스스로 돈다 (P2)

장이 열리면 봇이 자기 주기대로 판정하고, 시그널과 모의 체결을 기록한다. 이 동안 LLM 은 한 번도 호출되지 않는다. 차트에는 언제 사고 팔았는지가 마커로 남는다.

**왜 P2 인가**: 백테스트로 검증된 봇이 있어야 굴릴 의미가 있다.

**독립 테스트**: 장중에 봇을 켜두고 시그널 로그와 차트 마커가 쌓이는지로 검증된다.

**수용 시나리오**:

1. **Given** 봇을 켠 상태, **When** 장중에 조건이 충족되면, **Then** 시그널이 기록되고 모의 포지션이 갱신된다
2. **Given** 봇이 거래를 기록한 상태, **When** 그 종목의 차트를 열면, **Then** 매수·매도 지점이 마커로 표시된다
3. **Given** 봇이 도는 동안, **When** LLM 호출 로그를 확인하면, **Then** 장중 호출이 0건이다

---

### 사용자 스토리 5 — 원할 때 LLM 에게 묻고 시킨다 (P2)

터미널의 AI 콘솔에 지금 보고 있는 종목·기간·봇이 자동으로 실려 있다. "이 종목으로 골든크로스 전략 만들어줘"라고 하면 전략 파일이 만들어지고 바로 백테스트가 돌아 결과를 보여준다. 승인하면 반영되고, 승인하지 않으면 아무것도 바뀌지 않는다.

**왜 P2 인가**: 전략을 만드는 마찰을 크게 낮추지만, 봇·백테스트가 있어야 의미가 있다.

**수용 시나리오**:

1. **Given** 종목을 선택한 상태, **When** AI 콘솔에 종목을 말하지 않고 요청, **Then** 선택된 종목을 문맥으로 답한다
2. **Given** LLM 이 변경을 제안한 상태, **When** 승인하지 않고 화면을 벗어나면, **Then** 시스템 상태가 바뀌지 않는다
3. **Given** 성과가 기준 이하인 봇이 있는 상태, **When** 자동 조치가 실행되면, **Then** 봇이 정지되고(가역) 그 사실이 기록되며, 설정 변경·삭제는 일어나지 않는다

---

### 사용자 스토리 6 — 남이 받아서 자기 컴퓨터에 띄운다 (P2)

레포를 클론한 사람이 문서만 보고 기동해, 자기 데이터 소스 키를 넣고 자기 화면을 띄운다.

**왜 P2 인가**: 오픈소스 배포의 목표(G1)지만, 띄울 것이 있어야 의미가 있다.

**수용 시나리오**:

1. **Given** 처음 클론한 상태, **When** README 절차를 따르면, **Then** 별도 문의 없이 로그인 화면까지 도달한다
2. **Given** 데이터 소스 키가 없는 상태, **When** 기동하면, **Then** 키 없이도 기동되고 어떤 패널이 왜 비어 있는지 안내된다

---

### 사용자 스토리 7 — 실계좌를 옆에 놓고 비교한다 (P3)

내 실제 보유·손익을 조회해 화면에 띄우고, 같은 기간 봇들이 했다면 어땠을지를 나란히 본다.

**왜 P3 인가**: 실주문 승격의 판단 근거가 되지만 증권사 계좌 연동이 전제다.

---

### 엣지 케이스

- **데이터 소스 한도 소진** — 적재 중 한도에 걸리면 어디까지 받았는지 기록하고 다음 실행이 이어받는다. 화면은 "언제 기준 데이터"인지 표시한다.
- **시장이 다른 종목** — 같은 패널이라도 국내는 되고 미국은 안 되는 데이터가 있다. 패널은 시장별로 가용 여부를 판단해 없으면 이유를 표시한다.
- **적재되지 않은 종목 선택** — 유니버스 밖 종목을 열면 캔들이 없다. 빈 차트가 아니라 "적재 대상이 아님"과 적재 요청 경로를 보여준다.
- **장 마감·휴장** — 봇이 돌지 않는 시간대와 휴장일에 시그널이 만들어지지 않는다.
- **백테스트 구간에 데이터 공백** — 상장 이전 구간이나 거래 정지 기간이 포함되면 결과가 왜곡된다. 공백을 감지해 리포트에 표시한다.
- **워크스페이스 전환 중 진행 중 작업** — 백테스트가 도는 중에 워크스페이스를 바꾸면 그 작업의 소유가 흔들리지 않아야 한다.
- **동일 종목 중복 적재** — 같은 구간을 다시 받으면 중복 행이 아니라 갱신이어야 한다.

## 요구사항

### 기능 요구사항 — 터미널 골조 (P1)

- **FR-001**: 사용자는 터미널 한 화면에서 여러 패널을 동시에 볼 수 있어야 한다
- **FR-002**: 시스템은 선택된 종목·캔들 주기·기간을 화면 전체의 공유 문맥으로 유지해야 한다
- **FR-003**: 사용자가 종목을 바꾸면 열려 있는 모든 패널이 그 종목의 데이터로 갱신되어야 한다
- **FR-004**: 사용자는 패널을 이동·크기 조절·접기·닫기·다시 열기 할 수 있어야 한다
- **FR-005**: 시스템은 패널 배치를 워크스페이스별로 저장하고 복원해야 한다
- **FR-006**: 사용자는 사이드바에서 관심종목·스크리너 결과·보유종목을 전환하며 종목을 선택할 수 있어야 한다
- **FR-007**: 시스템은 종목 미선택 상태에서 브리핑(밤사이 시그널·승인 대기·봇 성과 요약)을 보여야 한다

### 기능 요구사항 — 데이터 적재 (P1)

- **FR-008**: 시스템은 종목 마스터(티커·종목명·시장·업종)를 적재하고 갱신해야 한다
- **FR-009**: 시스템은 일봉을 적재해 로컬에 보관해야 한다 — **국내 전 종목 10년 + 미국은 관심종목 규모(수십 종목) 10년**
- **FR-046**: 시스템은 분봉을 적재해 로컬에 보관해야 한다 — **관심종목·봇 유니버스 한정**. 일봉과 달리 전 종목 적재는 저장량상 불가(국내 전 종목 1분봉 10년 ≈ 27억 행)
- **FR-047**: 시스템은 보고 있는 종목의 호가·체결을 실시간으로 표시해야 한다 — **한 번에 한 종목만 구독**하고, 종목을 바꾸면 구독을 옮긴다. 호가는 적재 대상이 아니다(과거 호가는 무료 범위 밖)
- **FR-048**: 시스템은 사이드바의 여러 종목 시세를 **주기적 일괄 조회**로 갱신해야 한다 — 종목 수만큼 실시간 구독을 걸지 않는다
- **FR-049**: 봇은 실시간 구독이 아니라 **자기 판정 주기마다 조회**하는 방식으로 동작해야 한다 — 구독 수 제한과 무관해야 한다
- **FR-010**: 시스템은 적재 이력(언제 어디까지·무엇이 실패)을 기록하고 화면에 보여야 한다
- **FR-011**: 시스템은 저장된 각 행에 어느 소스에서 왔는지를 기록해야 한다
- **FR-012**: 사용자는 데이터 소스 API 키를 **자기 `.env` 에** 넣어 쓸 수 있어야 한다 (~~워크스페이스 단위로 등록·수정~~ — 2026-08-07 리드 결정으로 대체됨. 로컬 배포판 우선이라 워크스페이스별 키가 의미가 없다. **호스팅 모드에서는 성립하지 않으므로 그때 이 항목을 다시 판단한다** — `CONTEXT.md` 결정 로그)
- **FR-013**: 시스템은 데이터 소스 키가 없어도 기동되어야 하며, 어떤 기능이 왜 비어 있는지 안내해야 한다
- **FR-014**: 시스템은 같은 구간을 다시 적재할 때 중복을 만들지 않아야 한다
- **FR-015**: 시스템은 수정주가 처리 방식을 한 가지로 통일하고 무엇을 적용했는지 기록해야 한다

### 기능 요구사항 — 패널 (P1)

- **FR-016**: 차트 패널은 적재된 캔들을 표시하고 주기(분·일·월)를 전환할 수 있어야 한다
- **FR-017**: 차트 패널은 기술적 지표를 겹쳐 그릴 수 있어야 한다
- **FR-018**: 차트 패널은 매매 지점·시그널·목표가를 마커로 표시할 수 있어야 한다
- **FR-019**: 각 패널은 자기 데이터의 출처와 기준 시각을 표시해야 한다

- **FR-022**: 공시·뉴스·리서치 문서 패널은 선택된 종목 관련 항목을 표시해야 한다

### 기능 요구사항 — 워크스페이스 (P1)

- **FR-023** *(구현됨 — `tn_workspace_member`)*: 시스템은 한 사용자가 여러 워크스페이스에 속할 수 있는 관계를 지원해야 한다. **M2 에서는 데이터 관계만 갖추고 화면은 워크스페이스 하나만 쓴다** — 전환 UI 와 게스트 초대는 P2
  — 근거: 인증·세션·격리 경로를 두 번 건드리는 것이 가장 위험하다. 관계를 먼저 바꿔 그 위험을 한 번으로 끝낸다
- **FR-024**: 시스템은 워크스페이스 단위로 관심종목·설정·레이아웃·데이터 키를 격리해야 한다

- **FR-050** *(구현됨 — 예외는 투자 도메인의 발행사·법적 문서의 서비스 제공자·이력 문서뿐)*: "회사"라는 이름을 **화면·코드·DB 전 계층에서 "워크스페이스"로 통일**해야 한다 — 관계를 다대다로 바꾸는 작업과 **같은 작업에서** 수행한다(같은 테이블을 두 번 건드리지 않기 위함)

### 기능 요구사항 — 봇·전략 (P2)

- **FR-026**: 시스템은 전략 파일의 파라미터 선언을 읽어 봇 생성 폼을 만들어야 한다
- **FR-027**: 사용자는 여러 전략을 조합하고 결합 규칙·유니버스·자금 배분·리스크 규칙을 지정해 봇을 만들 수 있어야 한다
- **FR-028**: 시스템은 전략이 선언한 캔들 주기가 서로 달라도 한 봇 안에서 함께 동작하게 해야 한다
- **FR-029**: 사용자는 기간과 유니버스를 지정해 백테스트를 실행할 수 있어야 한다
- **FR-030**: 백테스트 결과는 사용된 가정(체결 기준·수수료·슬리피지·기간·유니버스)을 함께 표시해야 한다
- **FR-031**: 시스템은 봇별 성과 지표를 표시하고 정렬 기준을 바꿀 수 있게 해야 한다
- **FR-032**: 봇은 장중에 자기 주기대로 판정하고 시그널·모의 체결을 기록해야 한다
- **FR-033**: 시스템은 봇의 판단 근거(어떤 조건이 언제 충족됐는지)를 사후에 조회할 수 있게 해야 한다
- **FR-034**: 시스템은 봇에 신원을 부여해 어떤 봇이 무엇을 했는지 기록해야 한다

### 기능 요구사항 — 스크리너·유니버스 (P2)

- **FR-036**: 시스템은 정해진 시각에 스크리너 결과(후보 풀)를 다시 계산해야 한다
- **FR-037**: 관심종목은 스크리닝 조건과 무관하게 항상 유니버스에 포함되어야 한다

### 기능 요구사항 — LLM·AI 콘솔 (P2)

- **FR-038**: AI 콘솔은 현재 화면 문맥(종목·기간·선택 봇)을 자동으로 포함해야 한다
- **FR-039**: 사용자는 자연어·이미지·파일을 입력할 수 있어야 한다
- **FR-040**: LLM 이 제안한 변경은 사용자가 승인해야만 반영되어야 한다
- **FR-041**: 시스템은 되돌릴 수 있는 조치(봇 정지·알림·리포트)만 자동 실행해야 하며, 삭제는 자동으로 실행하지 않아야 한다
- **FR-042**: 시스템은 정해진 시각에 연구 배치를 실행하고, 같은 작업을 사용자가 임의 시점에 실행할 수 있게 해야 한다

### 기능 요구사항 — 배포 (P2)

- **FR-044**: 시스템은 로컬 모드와 호스팅 모드를 구분하고, 모드에 따라 AI 콘솔의 권한과 주문 기능 활성 여부를 달리해야 한다
- **FR-045**: 레포를 처음 받은 사람이 문서만으로 기동할 수 있어야 한다

### 비기능 요구사항

### 핵심 엔티티

- **워크스페이스** — 격리 단위. 관심종목·봇·전략 설정·레이아웃·데이터 키를 소유
- **종목** — 티커·종목명·시장·업종. 시장별로 식별 체계가 다름
- **캔들** — 종목·주기·시각별 시가/고가/저가/종가/거래량. 출처와 수정주가 여부를 함께 보관
- **전략** — 파일로 존재. 파라미터 선언·보는 주기·판정 로직
- **봇** — 전략 조합 + 결합 규칙 + 유니버스 + 배분 + 리스크. 워크스페이스에 속하고 자기 신원을 가짐
- **시그널** — 어떤 봇이 언제 어떤 조건으로 무엇을 판정했는가
- **모의 포지션·체결** — 봇의 가상 계좌 상태와 거래 기록
- **백테스트 실행** — 대상 봇·기간·유니버스·가정·결과 지표
- **레이아웃** — 워크스페이스별 패널 배치·크기·접힘 상태
- **적재 이력** — 소스·대상·구간·성공 여부·수행 시각

## 범위 밖

- **실주문** — 이번 범위에서 하지 않는다. 백테스트·검증이 끝난 뒤 별도로 판단한다
- **호스팅 SaaS 운영** — 로컬 배포판을 먼저 완성한다. 모드 분리만 설계에 반영한다
- **자동 매매의 전면 자동화** — 되돌릴 수 없는 조치는 승인을 거친다
- **모바일 전용 화면** — 데스크톱 터미널이 대상이다
- **암호화폐·파생상품** — 국내·미국 주식이 대상이다
- **여러 증권사 계좌 통합 조회** — 마이데이터는 개인이 취득할 수 없는 자격이 필요하다
- **에이전트 답변 품질·토큰 최적화** — 별도 베팅으로 분리한다

## 성공 기준

### 측정 가능한 결과

- **SC-001**: 처음 클론한 사람이 문서만 보고 기동해 로그인 화면에 도달한다 (외부 문의 0회)
- **SC-002**: 터미널에서 종목을 전환할 때 열린 패널이 모두 그 종목으로 갱신된다 (누락 패널 0개)
- **SC-003**: 바꾼 패널 배치가 재접속 후에도 유지된다
- **SC-004**: 차트에 표시된 캔들 값이 원본 소스 값과 일치한다
- **SC-005**: 화면의 모든 패널이 "실데이터" 또는 "임시 데이터 표시" 중 하나에 해당한다 (표시 없는 가짜 값 0개)
- **SC-006**: 적재 실행 후 어디까지 받았는지·무엇이 실패했는지가 화면에서 확인된다
- **counter-metric**: 화면을 빨리 채우려고 임시 데이터 표시 없는 값이 늘지 않는가 — 표시 없는 임시 값이 하나라도 있으면 SC-005 실패로 본다
- **counter-metric**: 패널을 늘리려고 데이터 출처 없는 패널이 늘지 않는가

## 가정

- 사용자는 데이터 소스에 직접 가입해 자기 API 키를 발급받을 수 있다
- **사용자는 국내·미국 증권사의 모의계좌를 개설한다** — 호가·국내 분봉·수급이 여기에 의존한다
- 대상 시장은 국내(KOSPI/KOSDAQ)와 미국(NASDAQ/NYSE)이다
- 기본 캔들 주기는 일봉이고, 분봉은 유니버스를 좁혀 확보 가능한 범위 안에서 다룬다
- 5·15·30·60분봉은 1분봉에서 합성한다 — 별도 적재하지 않는다
- 봇은 결정론적으로 동작하며 장중 LLM 호출이 없다
- 기존 인증·멀티테넌시 구조를 재사용한다
- 로컬 배포판을 먼저 완성하고 호스팅은 이후에 판단한다

## Clarifications

### 세션 2026-07-28

- Q: 한 사용자가 워크스페이스를 여러 개 갖게 할 것인가 (현재는 1인 1회사 단일 관계) → A: **관계만 미리 다대다로 바꾸고 전환 UI·게스트 초대는 P2**. 인증·격리 경로를 두 번 건드리지 않기 위함. (리드가 재검토 여지를 남김 — 바뀌면 FR-023 과 이 줄을 함께 갱신한다)
- Q: M2 의 적재 범위 — 어느 시장, 몇 종목, 몇 년 → A: **국내 전 종목 + 미국 소수 종목, 일봉 10년.** 시장이 둘이라는 사실이 심볼 정규화와 provider 추상화를 실제로 시험하므로 M2 에서 확인한다. 미국 규모는 작게 잡아 한도 관리가 M2 를 잡아먹지 않게 한다
- Q: 분봉·호가·거래량도 지원할 것인가 → A: **전부 지원하되 성격이 다르다.** 거래량은 캔들에 포함(별도 작업 아님). 분봉은 **유니버스 한정 적재**(전 종목은 저장량상 불가, 국내는 소스 상한이 1분봉·1년). 호가는 **적재가 아니라 실시간 구독**이며 과거 호가는 무료 범위 밖
- Q: 증권사 계좌를 열 것인가 (호가·국내분봉·수급의 전제) → A: **국내·미국 모두 모의계좌를 연다.** 모의와 실계좌가 같은 API 인 곳을 골라 실주문 승격 시 코드를 재사용한다
- Q: "회사"를 무엇으로 부를 것인가 (리네이밍 범위) → A: **화면·코드·DB 전 계층에서 "워크스페이스"로 통일.** 관계를 다대다로 바꾸는 작업과 같은 작업에서 수행해 같은 테이블을 두 번 건드리지 않는다
- Q: 실시간 스트리밍은 한 종목만 구독하고 나머지는 적재·호출로 채우는 것이 맞는가 → A: **맞다.** 세 갈래로 정리 — ① 과거 캔들은 DB 에서 읽고 ② 호가·체결은 보고 있는 한 종목만 웹소켓 구독(적재 안 함) ③ 재무·공시·뉴스는 필요할 때 REST. 사이드바 다종목 시세는 주기적 일괄 조회, 봇은 판정 주기마다 조회 — 둘 다 구독 수 제한과 무관하게 설계한다
